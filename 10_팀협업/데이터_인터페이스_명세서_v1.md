## 1. 시스템 데이터 흐름 (전체 개요)

```
┌──────────────────┐
│  mmWave 레이더    │  ← 하드웨어
│  (Raw 4D Point   │
│   Cloud Stream)  │
└────────┬─────────┘
         │  Stage 1 Input
         ▼
┌──────────────────┐
│ 서승원 — DSP 필터  │  Adaptive LMS, EMI 노이즈 제거
└────────┬─────────┘
         │  Stage 1 Output / Stage 2 Input
         │  (필터링된 신호)
         ▼
┌──────────────────┐
│ 홍성준 — 이상 탐지 │  LSTM-Autoencoder, FMCW 위상 분석
└────────┬─────────┘
         │  Stage 2 Output / Stage 3 Input
         │  (이상 이벤트)
         ▼
┌──────────────────┐
│ 유빈 — RAG + UI   │  pgvector + Qwen2.5 + Streamlit
└────────┬─────────┘
         │  Stage 3 Output
         ▼
┌──────────────────┐
│ 사용자 (관제실)    │
│ + 스마트 차단기   │
└──────────────────┘
```

## 2. 단계별 데이터 포맷

### 📥 Stage 1 → Stage 2 (서승원 → 홍성준)

**의미**: 노이즈 필터링이 끝난 깨끗한 신호.

```json
{
  "schema_version": "1.0",
  "timestamp": "2026-06-05T12:01:03.123Z",
  "zone_id": "C",
  "filtered_signal": {
    "point_cloud": [
      {"x": 1.2, "y": 0.5, "z": 1.7, "doppler": -0.2, "intensity": 0.8}
    ],
    "vibration_spectrum": {
      "frequency_hz": [10.5, 24.2, 60.0, 120.0],
      "amplitude": [0.001, 0.05, 0.002, 0.0001]
    },
    "micro_motion": {
      "phase_um": [0.5, 0.7, 0.6, 0.8],
      "sample_rate_hz": 100
    }
  },
  "metadata": {
    "noise_level_before": 0.45,
    "noise_level_after": 0.02,
    "signal_quality": 0.95,
    "filter_method": "LMS_adaptive"
  }
}
```

| 필드 | 타입 | 설명 | 필수 |
|------|------|------|------|
| `timestamp` | ISO8601 string | 데이터 생성 시각 (UTC) | ✅ |
| `zone_id` | string | 구역 ID ("A", "B", "C") | ✅ |
| `filtered_signal.point_cloud` | array | 4D 포인트 (x,y,z,doppler,intensity) | ✅ |
| `filtered_signal.vibration_spectrum` | object | 진동 주파수 스펙트럼 | ✅ |
| `filtered_signal.micro_motion` | object | 마이크로미터 단위 움직임 | 선택 |
| `metadata.signal_quality` | float (0~1) | 신호 품질 점수 | ✅ |

### 📥 Stage 2 → Stage 3 (홍성준 → 유빈)

**의미**: 이상 탐지 결과. 사고/위험 이벤트 발생 알림.

```json
{
  "schema_version": "1.0",
  "timestamp": "2026-06-05T12:01:05.456Z",
  "event_id": "evt_20260605_120105_C001",
  "event_type": "fall_detected",
  "zone_id": "C",
  "severity": "critical",
  "confidence": 0.92,
  "details": {
    "description": "작업자 낙상 확정 (자세 붕괴 + 속도 임계 초과)",
    "worker_pose": {
      "posture": "collapsed",
      "velocity_m_s": 0.05,
      "height_m": 0.3
    },
    "equipment_anomaly": null,
    "anomaly_score": 0.87,
    "reconstruction_error": 0.045
  },
  "event_log": [
    {"time": "12:01:03", "msg": "Zone C - Body posture collapse detected"},
    {"time": "12:01:04", "msg": "Zone C - Velocity drop below threshold"},
    {"time": "12:01:05", "msg": "Zone C - Fall event confirmed"}
  ],
  "raw_signal_ref": "filtered_20260605_120103.json"
}
```

| 필드 | 가능한 값 | 설명 |
|------|---------|------|
| `event_type` | `fall_detected` / `electric_shock_risk` / `pinching` / `vibration_anomaly` | 이벤트 종류 (4가지) |
| `severity` | `normal` / `warning` / `critical` | 위험도 |
| `confidence` | 0.0 ~ 1.0 | 탐지 신뢰도 |
| `details` | object | 이벤트별 세부 데이터 |
| `event_log` | array | 시간순 탐지 단계 (UI Event Log에 표시) |

#### 4가지 이벤트 유형별 `details` 구조

**`fall_detected`** (낙상):
```json
"details": {
  "worker_pose": { "posture": "collapsed", "velocity_m_s": 0.05, "height_m": 0.3 },
  "anomaly_score": 0.87
}
```

**`electric_shock_risk`** (감전 위험):
```json
"details": {
  "proximity_m": 0.15,
  "equipment_voltage_kv": 22.9,
  "approach_speed_m_s": 1.2
}
```

**`pinching`** (협착):
```json
"details": {
  "equipment_id": "rotor_03",
  "body_part_proximity_m": 0.05,
  "rotation_rpm": 1800
}
```

**`vibration_anomaly`** (진동 이상):
```json
"details": {
  "equipment_id": "motor_02",
  "rms_vibration_um_s": 1.8,
  "threshold_um_s": 1.0,
  "frequency_anomaly_hz": 47.5,
  "bearing_fault_suspected": true
}
```

## 3. 시나리오 4개 샘플 데이터

각 시나리오마다 Stage 1·2·3 샘플은 다음 파일들에 저장 예정:

```
공모전\팀협업\샘플데이터\
├── scenario_01_fall\
│   ├── stage1_filtered.json
│   ├── stage2_event.json
│   └── stage3_rag_response.json
├── scenario_02_electric_shock\
├── scenario_03_pinching\
└── scenario_04_vibration\
```

> 📌 **샘플 데이터 파일들은 명세서 합의 후 별도 작성 예정.**

### 시나리오 간략 요약

| # | 이벤트 | Zone | 핵심 데이터 | 기대 RAG 답변 출처 |
|---|--------|------|------------|----------------|
| 1 | 낙상 (Fall) | C | 자세 붕괴, 속도 < 0.1 m/s | sop2.pdf (H-187 산업재해 응급처치) |
| 2 | 감전 위험 (Electric Shock) | A | 작업자 ↔ 고압설비 거리 < 0.3 m | sop.pdf (E-14 감전응급), E-105 |
| 3 | 협착 (Pinching) | B | 회전체 5cm 이내 접근 | B-M-37 회전기계 끼임·절단 |
| 4 | 진동 이상 (Vibration) | C | RMS 진동 > 1.0 μm/s | M-121, M-131, M-146 예지보전 |

## 4. 통신 방식 (시연 단계)

### 6월 5일 컨셉 시연용 (가장 간단)

각자 결과를 JSON 파일로 저장해서 다음 단계가 읽음:

```
[서승원] → C:\radar-guard\pipeline\stage1_filtered.json 저장
[홍성준] ← 위 파일 읽음 → C:\radar-guard\pipeline\stage2_event.json 저장
[유빈]   ← 위 파일 읽음 → Streamlit 화면 갱신
```

장점: 구현 가장 쉬움, 디버깅 편함
단점: 실시간 아님 (배치 처리)

### 향후 실제 운영용 (Phase 4~5에서 결정)
- MQTT (가벼움, IoT 표준)
- ZeroMQ (저지연)
- REST API (Streamlit-Streamlit 통신)
- 멘토님 PPT에 *"ROS 배제형 MQTT/ZeroMQ"* 명시 (슬라이드 6)

→ **실제 통합은 5월 1~2주 P1의 아키텍처 설계 결정 따름.**

## 6. 합의 후 확정 사항

다음 항목들은 팀 미팅 후 결정해서 v2에 반영:

- [ ] Zone ID 표기 통일 ("A/B/C" vs "1/2/3" 등)
- [ ] 시간 표기 통일 (UTC vs KST, 정밀도)
- [ ] 통신 방식 최종 결정 (시연용 / 운영용)
- [ ] `event_type` 추가 필요 여부 (위 4개로 충분한지)
- [ ] `severity` 임계값 기준 (각 이벤트별 confidence 범위)
- [ ] 에러 처리 표준 (필터링 실패, 탐지 실패 시 어떻게)
