# 다음 작업 시작

## 이 스킬이 있는 이유

Cowork(기획·설계)와 Claude Code(구현)는 **기억을 공유하지 않고, 서로를 직접 호출할 수도 없다.**
그래서 지시는 `HANDOFF.md` §1 에 파일로 남긴다. 사용자가 긴 지시를 손으로 옮기지 않아도 되게 하는 것이 이 스킬의 목적이다.

`HANDOFF.md` §1 은 **Cowork 가 쓴 작업 지시서**다. 사용자가 그 자리에서 구두로 지시한 것과 같은 무게로 다룬다.

## 순서

### 1. 읽는다
`HANDOFF.md` 전체를 읽는다. 세션 시작 시 이미 로드됐더라도 **다시 읽는다** — Cowork 가 그 사이에 고쳤을 수 있다.

- **§0**: 현재 상태와 우선순위
- **§1**: 지시 (Cowork 영역 — 읽기만 한다)
- **§2**: 지난 세션에 내가 남긴 것 (중복 작업 방지)

### 2. 무엇을 할지 정한다
§0 의 "다음 최우선"과 §1 의 순위 표시(`1순위`, `2순위`…)를 따른다.
§2 에 이미 끝났다고 적힌 것은 건너뛴다.

**보류·중단 표시를 존중한다.** §1 에 "보류", "손대지 말 것", "원인 규명까지만" 같은 제약이 있으면 그 선에서 멈춘다.

### 3. 계획을 먼저 말한다 — 코드를 고치기 전에

사용자에게 이렇게 보고한다.

- **무엇을** 할 것인가 (§1 의 어느 항목인가)
- **왜** 그 순서인가
- **어떻게** 확인할 것인가 (무엇을 측정·출력해서 원인을 짚을 것인가)
- §1 의 제약 중 **이 작업에 걸리는 것**

파일 3개 이상 또는 100줄 이상이 바뀔 작업이면 **plan mode 로 전환**한다.

**승인 없이 코드를 고치지 않는다.** §1 에 "원인을 먼저 글로 설명하고 승인받은 뒤에 고친다"가 공통 규칙으로 적혀 있다.

### 4. 막히면 멈춘다
§1 의 지시가 실제 코드와 어긋나거나, 지시대로 하면 `CLAUDE.md` 의 금지사항을 어기게 되면 **그대로 진행하지 말고 사용자에게 묻는다.**
임의로 판단해서 다르게 했다면, 나중에 §2 에 **무엇을 왜 다르게 했는지** 반드시 적는다.

### 5. 끝나면
`session-end` 스킬로 마무리한다 — 검증 → §2 갱신 → 커밋.

## 하지 말 것
- **§1 을 수정하는 것.** Cowork 영역이다. 다 끝난 항목이라도 지우지 않는다. 보고는 §2 에 한다.
- 승인 없이 코드 수정
- §1 에 없는 작업을 임의로 끼워넣기
- §1 이 비어 있는데 뭐라도 만들어내기 → 그럴 땐 "§1 에 지시가 없다"고 알리고 무엇을 할지 묻는다
