# Radar-Guard UI 디자인 시스템 — 실제 값

> **이 문서는 기록이지 사양이 아니다.** 지금 코드가 어떤 값을 쓰고 있는지 적어 둔 것이며,
> "이렇게 해야 한다"는 뜻이 아니다. 값을 바꾸는 제안은 언제든 가능하다 —
> 단 `SKILL.md` §1(HARD CONSTRAINTS)을 어기지 않아야 하고, 바꾼 뒤에는 검증을 다시 돌린다.
>
> **예외 — 여기서 탐색 대상이 아닌 것 둘.** 이 둘은 `SKILL.md` §1 에 속한다.
> ① `RED` 가 위험 등급 전용이라는 **의미 규칙** (구체적 hex 값은 바꿔도 된다)
> ② 대비비 **4.5:1 / 3:1** 하한 (WCAG 기준, 밝은 관제실이라 안전 문제다)
>
> 여기 있는 값은 전부 코드에서 읽었거나 계산으로 확인했다. 목표값·제안값은 넣지 않았다.
> 기준 시점: 2026-08-03.

## 2. 색 — 라이트 (확정, 미적용)

착수는 **8/05 젯슨 통합시험 이후**. 배경만 뒤집으면 경보색이 안 읽힌다.
전부 라이트 패널 `#FFFFFF` 기준 **4.5:1 이상**. 계산은 WCAG 2.1 상대 휘도 공식.

| `PANEL_HI` | `#F1F5F9` | — | — |

### 2.1 라이트에서 `FAINT` 를 `DIM` 과 같게 두는 이유

`FAINT` 는 캡션(9pt)에 쓰인다. slate-500 `#64748B` 는 흰 배경에서 4.76:1 로 아슬아슬하고, **9pt 에서는 대비비를 통과해도 실제로 안 읽힌다** — `radar_common.py:315` 의 "8pt DIM 은 실제로 안 읽혔다"는 실측 기록과 같은 문제다. 비활성 표현은 색이 아니라 다른 수단으로 한다(예: 평면도의 '장비 미설치'는 채운 사각 `■` 대신 빈 사각 `□`).

### 2.2 상태 배경 (라이트) — 점멸 방향이 반대다

| 상수 | 라이트 값 |
|---|---|
| `BG_ALERT` | `#FEF2F2` |
| `BG_ALERT_HI` | `#FEE2E2` |
| `BG_OK` | `#F0FDF4` |
| `BG_WARN` | `#FFFBEB` |
| `BG_SEL` | `#ECFEFF` |

다크는 배경을 **밝게** 해서 점멸을 만들지만(`#2A1214` → `#3B1518`), 라이트는 **진하게** 해야 눈에 띈다(`#FEF2F2` → `#FEE2E2`). 그대로 두면 라이트에서 점멸이 거의 안 보인다.

## 3. 타이포 (현행, `console_ui.py:134~140`)

`f(size)` 는 `QFont(FONT, size)` 를 만든다. **두 번째 인자는 pointSize** 이므로 96 DPI 에서 px = pt × 4/3.

| 상수 | pt | px(96dpi) | 용도 |
|---|---:|---:|---|
| `F_DISPLAY` | 26 | 34.7 | 대시보드 제목 |
| `F_H1` | 19 | 25.3 | 화면 제목 · 상태 제목 |
| `F_H2` | 15 | 20.0 | 카드 제목 |
| `F_BODY` | 11 | 14.7 | 본문 · 버튼 |
| `F_LABEL` | 10 | 13.3 | 라벨 |
| `F_CAP` | 9 | 12.0 | 캡션 |

**측정된 사실 (판단 아님)**

- 단계 간 비율: 1.368 / 1.267 / 1.364 / **1.100 / 1.111** — 일관된 모듈러 스케일이 아니다. 하위 세 단계(11·10·9pt)는 1.1배씩이라 크기 차이가 거의 없다.
- `F_BODY` 14.7px 는 데스크톱 본문 권장 하한 16px 에 못 미친다.
- 한 화면에 6단계를 모두 쓴다. `qt-ui-design` 은 화면당 3~4단계를 권한다.

**⚠ 목표값은 정하지 않았다.** 폰트 크기 변경은 글자 폭을 바꿔 잘림을 유발한다 — 2026-08-02 에 레이아웃 9건이 폰트 문제로 발생한 전례가 있다. 8/05 이후 라이트 모드와 함께 판단한다.

**폰트 패밀리는 `resolve_font()` 가 설치된 것 중에서 고른다.** offscreen 검증에서는 `QT_QPA_FONTDIR` 를 지정해야 `families()` 가 0 이 아니다.

## 5. 컴포넌트 헬퍼 (`console_ui.py`)

새 위젯을 만들 때 이 헬퍼를 쓴다. 직접 `setStyleSheet` 로 색을 박지 않는다.

| 헬퍼 | 시그니처 | 비고 |
|---|---|---|
| `lb()` | `lb(text, size=F_BODY, color=TXT, bold, wrap, align)` | 라벨 |
| `eyebrow()` | `eyebrow(text)` | 섹션 소제목 |
| `card()` | `card(bg=PANEL, border=None, radius=RADIUS)` | 패널 |
| `button()` | `button(text, kind='ghost', size, height=36, width)` | `kind`: `primary`(시안·주 액션) / `danger`(빨강·경보 대응) / `ghost`(외곽선) / `quiet`(배경만) |
| `vbox()` `hbox()` | `(w, m=SP4, s=SP3)` | 레이아웃 |
| `scrollable()` | `scrollable(inner, hbar=False)` | **세로가 모자랄 수 있는 열은 반드시 감싼다** |
| `styled_combo()` `styled_line()` | | 입력 |

**`scrollable()` 이 중요한 이유**: 세로가 모자라면 Qt 는 최소크기까지 눌러 담고, 그래도 모자라면 **위젯을 겹쳐 그린다.** 실측에서 버튼이 다른 버튼 위에 포개지고 계측 타일의 숫자가 겹쳤다. 경보 화면에서 숫자가 겹치는 것은 '못 읽는 것'이 아니라 **'잘못 읽는 것'**이라 훨씬 위험하다.

### 5.1 현재 레이아웃과 그 이유 (실측 근거)

**⚠ 아래는 규칙이 아니라 현재 해법이다** (`SKILL.md` §3 HEURISTICS). 각 항목은 §1 의 제약을
만족시키려고 고른 것이다. **같은 제약을 다른 배치로 만족시킬 수 있다면 바꿔도 된다** —
바꿀 때는 괄호 안의 문제가 재발하지 않음을 보여야 한다.

- **실시간 계측 타일 4칸은 왼쪽 열 하단에 둔다.** 우측에 두면 경보 시 사고 패널이 들어오며 4개 중 2개와 구역 현황이 스크롤 밖으로 밀린다.
- **보조 도구 버튼 4개는 스크롤 밖에 둔다.** 우측 열 안에 두면 경보 패널이 밀어내 반쯤 잘린다.
- **평면도 구역 색은 패킷마다(10 Hz) 갱신한다.** 700ms 주기 `refresh()` 에만 맡기면 경보 후 최대 0.7초 늦게 붉어지는데, 1.5초 뒤 자동 전환이라 그 지연이 그대로 보인다.
- **자세 캡션(`pose_lb`)은 wrap 하지 않고 말줄임한다.** 두 줄이 되면 장면 위젯 위로 겹쳐 그려진다.
