# Radar-Guard HMI

**This skill is a set of guardrails, not a visual template.**
Examples are non-binding. Claude may propose a substantially different solution
when it satisfies all hard constraints and provides a reasoned usability and
implementation justification.

산업 현장 안전 관제 시스템이다. 낙상·감전을 놓치면 사람이 다친다.
아래 네 층은 **구속력이 다르다.** 섞지 마라.

---

## 1. HARD CONSTRAINTS — 위반 불가

**기술**
- PyQt5 QtWidgets + QSS 로 구현한다. QML·React·Tailwind·HTML 로 전환하지 않는다.
- 시그널/슬롯·스레드·`RadarLink`·판정 로직을 보존한다. 표시 계층만 대상이다.

**판정과 표시의 경계**
- 판정은 젯슨, 표시는 노트북. **UI 계산 결과를 판정에 되먹이지 않는다.**
- 판정 임계값을 UI 에서 편집 가능하게 만들지 않는다.
- 경과 시간은 **노트북 수신 시각** 기준. 젯슨은 RTC 가 없어 시계가 틀어진다.

**데이터 정직성**
- 없는 값은 `—`. 추정값·기본값으로 채우지 않는다. 관제 화면의 거짓 수치는 결함이다.
- 센티넬 값(`1e9` 등)을 화면으로 흘리지 않는다.
- **측정값과 추론값을 구분해 표시한다.** 원시 점군은 측정, 인체 도식·머리 추정점은 추론.
- 추적을 놓쳤으면 형상을 지우고 이유를 표시한다. 없는 자세를 그리지 않는다.
- 예외를 조용히 삼키지 않는다.

**경보 의미**
- 등급 매핑(`EVENT_SEV`)의 의미를 바꾸지 않는다. 낙상·감전·협착·과전류·전압강하 = `critical`,
  정지형·진동 = `warning`. 확정 사고와 확인 필요는 다르다.
- **RED 는 위험 등급 전용이다.** 등급이 있는 요소는 `sev_color(sev)` 로 색을 정한다.
  RED 를 등급과 무관하게 고정하지 않는다.
- **색만으로 상태를 전달하지 않는다.** 색 + (아이콘 또는 텍스트), 최소 2단서.
- **ACK 는 등급 색을 낮추지 않는다.** 확인했다고 위험이 사라진 게 아니다.
- 점멸은 미확인 + `critical` 에만.
- **경보 시 필요한 정보가 화면 밖으로 밀리지 않는다.** 겹쳐 그려지는 것은 특히 위험하다 —
  숫자가 겹치면 못 읽는 게 아니라 잘못 읽는다.

**접근성**
- 본문 대비 4.5:1, 큰 텍스트(19px bold 이상) 3:1 이상. 실제 사용 환경은 **밝은 관제실**이다.

**검증**
- 표시 계층을 고쳤으면 `ui-verify` **전체**를 돌린다. 기준: v1 결함 35항목 0건 /
  레이아웃 4해상도 0건 / 실데이터 재생 64항목 0건 / 평면도 흐름 16항목 0건, pyflakes 0.
- 색·등급을 고쳤으면 `replay_*.png` 를 **직접 열어** 등급별 색을 눈으로 확인한다.

물리 한계(각분해능 28°, 정지한 사람 미검출 등)는 `CLAUDE.md` §8 이 정본이다.

## 2. DESIGN PRINCIPLES — 방향, 판단 여지 있음

- **정보 위계**: 관제의 질문 순서는 어디 → 무엇 → 왜 → 무엇을 누를까.
- **평소와 경보를 분리한다.** 경보 시엔 볼 것만 남는다.
- **화면에 설명을 쓰지 않는다.** 근무자는 읽지 않는다. 색과 위치로 말한다.
- **인지 부담 최소화.** 같은 정보를 같은 강도로 반복하면 위계가 사라진다.
- **일관성.** 같은 뜻은 같은 색·같은 위치.

원칙끼리 충돌하면 §1 을 해치지 않는 선에서 근거를 들어 선택하고, 그 근거를 남긴다.

## 3. HEURISTICS — 현재 해법, 더 나은 근거가 있으면 바꿔도 된다

**⚠ 아래는 규칙이 아니라 지금까지의 답이다.** 각 항목은 §1 의 제약을 만족시키려고 고른 것이며,
같은 제약을 다른 방식으로 만족시킨다면 바꿔도 된다. **바꾸려면 그 제약을 어떻게 지키는지 설명한다.**

| 현재 해법 | 이게 지키려는 제약 |
|---|---|
| 실시간 계측 타일을 왼쪽 열 하단에 | 경보 시 정보가 스크롤 밖으로 밀리지 않게 (실측: 우측에 뒀을 때 4개 중 2개 밀림) |
| 보조 도구 버튼을 스크롤 밖에 | 같음 (실측: 반쯤 잘림) |
| 평면도 구역 색을 패킷마다(10 Hz) 갱신 | 경보 표시 지연 최소화 (700ms 주기면 최대 0.7초 늦음) |
| 자세 캡션을 wrap 없이 말줄임 | 겹쳐 그려짐 방지 (실측: 두 줄이 되면 장면 위에 겹침) |
| 3D 포인트 클라우드를 메인에 | 7/29 결정. 단 **점이 적은 것은 물리 한계라 2D 로 바꿔도 해결되지 않는다** |
| 카드 남용 최소화 · 조작은 한 단계 뒤 | 인지 부담 |

## 4. EXPLORATION PROTOCOL

**적용 대상: 화면 구조를 바꾸는 변경.** 영역 배치, 정보 그룹핑, 페이지 추가/삭제, 표시 항목의 이동.
색 하나 고치기, 문구 수정, 결함 수정 같은 국소 변경에는 적용하지 않는다.

1. 구현 전에 **서로 다른 정보구조 3안 이상**을 제안한다.
2. **색만 다른 변형은 다른 안으로 인정하지 않는다.**
3. 각 안을 **인지 속도 · 구현 위험 · PyQt5 적합성 · 데이터 정직성 · 운영자 부담**으로 비교한다.
4. **첫 번째 안을 자동으로 구현하지 않는다.** 추천안과 근거를 내고 **승인 후** 구현한다.
5. 검증된 결정만 `references/ui-design-system.md` 에 옮긴다. 미검증 아이디어는 옮기지 않는다.
