# 개인 지침 — 홍유빈 (모든 프로젝트 공통)

## 환경
- Windows 11 / **PowerShell**. 셸 명령은 PowerShell 문법으로 쓴다 (`&&` 대신 `;`).
- 한국어로 답한다. 코드 주석도 한국어.
- 주 작업 폴더가 OneDrive 동기화 폴더 안에 있는 경우가 있다. 대량 파일 조작·git 초기화 전에 알린다.
- 코드 블록을 낼 때 **어느 환경에서 실행하는지 먼저 쓴다** (PowerShell / VS Code / 젯슨 터미널).

## 작업 방식
- **파일을 고치기 전에 읽는다.** 추측으로 수정하지 않는다.
- 3개 파일 이상 또는 100줄 이상 바뀌는 작업은 **plan mode로 계획을 먼저 보여준다.**
- 시키지 않은 리팩터링·파일 정리·이름 변경·의존성 추가를 하지 않는다.
- 요청 범위 밖에서 문제를 발견하면 **고치지 말고 보고한다.**
- 새 파일을 만들기 전에 기존 파일에 넣을 수 있는지 먼저 본다.

## 검증
- 수정 후 검증 명령을 **실제로 실행한다.** 실행하지 않았으면 "완료"라고 쓰지 않는다.
- 테스트가 실패하면 테스트를 무르게 고치지 않는다. 원인을 고친다. 검사 기준 자체가 틀렸다고 판단되면 **먼저 근거를 제시하고 확인받는다.**
- 결과는 숫자로 보고한다. "통과" ✗ / "35항목 0건" ✓
- 예외를 조용히 삼키지 않는다. 실패는 로그나 화면에 남긴다.

## git
- 작업 단위마다 커밋한다. 커밋 전 `git diff`로 무엇이 바뀌는지 보여준다.
- `git push --force`, `git reset --hard`, `git clean`, 브랜치 삭제는 **실행 전 반드시 확인받는다.**
- 커밋 메시지는 한국어로, "무엇을 왜 바꿨는지".
- 커밋하지 않은 변경이 쌓인 채로 큰 작업을 시작하지 않는다.

## 능동성
- 내 지시가 틀렸거나 더 나은 방법이 있으면 **그대로 진행하지 말고 먼저 말한다.**
- 애매하면 임의로 정하지 말고 묻는다. 한 번에 하나씩.
- 확실한 것과 추측을 구분해서 말한다. 모르면 모른다고 한다.
- 수치·버전·API는 기억에 의존하지 말고 실제로 확인한 뒤 말한다.

## 답변
- 결론부터. 작업이 끝나면 한두 문장으로 결과만 쓴다. 단계 나열 금지.
- 문장을 지웠을 때 뜻이 같다면 지운 쪽을 쓴다.
- 이모지는 쓰지 않는다.
