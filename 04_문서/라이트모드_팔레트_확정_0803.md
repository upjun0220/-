# 라이트 모드 팔레트 확정 — 2026-08-03(월)

> **착수 시점: 8/05(수) 젯슨 통합시험 이후.** 이 문서는 색만 확정한다. 코드는 아직 건드리지 않는다.
> 구현 방식: **토큰 중앙화 + 전역 QSS 로 재시작 없이 즉시 전환.** 근거와 감사 숫자는 §4.

---

## 1. 왜 하는가

멘토 피드백(요지):

> "고보안 환경은 어두울 것이라고 가정한 접근은 실제 사용 환경을 깊이 고민해 본 훌륭한 시도였습니다.
> 산업 현장의 관제실, 변전실, 그리고 고보안 구역은 작업자의 물리적 안전 확보, 정밀한 설비 점검,
> 그리고 CCTV 모니터링을 위해 **의외로 조도를 상당히 밝게 유지**합니다."

현행 UI는 다크 전용이다. 밝은 관제실에서 다크 화면은 주변 조도와의 휘도 차 때문에 눈이 피로하고 반사가 심하다.

**단, 배경만 뒤집으면 더 나빠진다.** 지금 팔레트는 어두운 배경 기준으로 고른 것이라 흰 배경에서 경보색이 읽히지 않는다. 이 시스템은 **색이 곧 위험 등급**이므로(`CLAUDE.md` §4) 경보색이 안 보이는 것은 미관 문제가 아니라 **안전 결함**이다.

---

## 2. 문제 — 현행 색의 흰 배경 대비비

WCAG 2.1 상대 휘도 공식으로 계산했다(2026-08-03 산출).
기준: 본문 텍스트 **4.5:1**, 19px bold 이상 큰 텍스트 **3:1**.

| 색 | 용도 | 다크 패널 `#111827` | 흰 배경 `#FFFFFF` | 판정 |
|---|---|---:|---:|---|
| CYAN `#22D3EE` | 주 액션 · 선택 | 9.82:1 | **1.81:1** | **불가** |
| AMBER `#F59E0B` | 주의 · 사전경보 | 8.26:1 | **2.15:1** | **불가** |
| GREEN `#22C55E` | 정상 · 확인 | 7.79:1 | **2.28:1** | **불가** |
| RED `#EF4444` | 위험 · 경보 | 4.71:1 | 3.76:1 | **부분** |
| TXT `#F8FAFC` | 본문 | 16.96:1 | **1.05:1** | **불가** |
| DIM `#94A3B8` | 보조 | 6.92:1 | 2.56:1 | **불가** |

**RED가 "부분"인 이유**: 폰트 크기에 따라 갈린다.

- 경보 제목 `a_kind`(F_H1 = 19px bold) → 큰 텍스트 기준 3:1 → **통과**
- 이벤트 로그 표의 사고 종류(F_BODY = 11px), 판단 근거 표의 통과/미달(F_LABEL = 10px), 캡션(F_CAP = 9px) → 4.5:1 필요 → **미달**

즉 "빨강은 흰 배경에서도 보인다"는 **큰 제목에서만 맞다.**

**명암 방향도 뒤집어야 한다.** 다크는 창 배경(`#090D18`)보다 패널(`#111827`)이 **밝아서** 카드가 떠 보인다. 라이트에서 같은 효과를 내려면 배경을 회색, 패널을 흰색으로 둬야 한다. 단순 반전이 아니다.

## 3. 확정 팔레트

전부 라이트 패널 `#FFFFFF` 기준 **4.5:1 이상**이다.

| 상수 | 다크(현행) | **라이트(확정)** | 대비비 | 비고 |
|---|---|---|---:|---|
| `BG` 창 배경 | `#090D18` | `#F8FAFC` | — | 패널보다 어둡게 |
| `PANEL` 패널 | `#111827` | `#FFFFFF` | — | **배경보다 밝다(방향 반전)** |
| `PANEL_HI` 강조 패널 | `#151D2E` | `#F1F5F9` | — | |
| `PANEL_LO` 눌림·비활성 | `#0D1420` | `#E2E8F0` | — | |
| `EDGE` 테두리 | `#263247` | `#CBD5E1` | — | |
| `TXT` 본문 | `#F8FAFC` | `#0F172A` | 17.85:1 | |
| `DIM` 보조 | `#94A3B8` | `#475569` | 7.58:1 | |
| `FAINT` 비활성 | `#64748B` | `#475569` | 7.58:1 | **⚠ §3-1** |
| `CYAN` 주 액션 | `#22D3EE` | `#0E7490` | 5.36:1 | |
| `GREEN` 정상 | `#22C55E` | `#15803D` | 5.02:1 | |
| `AMBER` 주의 | `#F59E0B` | `#B45309` | 5.02:1 | |
| `RED` 위험 | `#EF4444` | `#B91C1C` | 6.47:1 | |

### 3-1. FAINT 를 DIM 과 같은 값으로 둔 이유

`FAINT` 는 캡션(F_CAP = 9px)에 쓰인다. slate-500 `#64748B` 는 흰 배경에서 4.76:1 로 아슬아슬하고, **9px 에서는 대비비를 통과해도 실제로 안 읽힌다** — `radar_common.py:315` 의 "8pt DIM 은 실제로 안 읽혔으므로 10pt 이상에만 쓴다"는 기록과 같은 문제다.

라이트에서는 `FAINT` 와 `DIM` 을 구분하지 않고 둘 다 `#475569` 로 둔다. **비활성 표현은 색이 아니라 다른 수단으로 한다** — 예: 평면도의 '장비 미설치'는 채운 사각(`■`)이 아니라 빈 사각(`□`)으로 이미 구분되어 있다.

### 3-2. 상태 배경색

다크는 저채도 **어두운** 배경, 라이트는 저채도 **밝은** 배경이다.

| 상수 | 다크 | 라이트 |
|---|---|---|
| `BG_ALERT` 경보 패널 | `#2A1214` | `#FEF2F2` |
| `BG_ALERT_HI` 배너 점멸 ON | `#3B1518` | `#FEE2E2` |
| `BG_OK` 완료 | `#0E2A1B` | `#F0FDF4` |
| `BG_WARN` 주의 | `#2A2008` | `#FFFBEB` |
| `BG_SEL` 선택·호버 | `#0E2A33` | `#ECFEFF` |

**점멸은 라이트에서 방향이 반대다.** 다크는 배경을 **밝게** 해서 점멸을 만들지만(`#2A1214` → `#3B1518`), 라이트는 **진하게** 해야 눈에 띈다(`#FEF2F2` → `#FEE2E2`). 이걸 그대로 두면 라이트에서 점멸이 거의 안 보인다.

## 4. 구현 방식 — 토큰 중앙화 + 전역 QSS (재시작 없이 즉시 전환)

> **[8/03 정정] 창 재생성안(구 B안)은 철회했다.** `console_ui.py:93` 이
> `from radar_common import (BG, PANEL, TXT, ...)` 로 **이름을 복사**하므로 창을 새로 만들어도
> 이미 바인딩된 값이 그대로다. 즉 **창 재생성도 전체 치환이 선행**이라 즉시 전환 대비 이점이 없다.

### 4-1. 감사 결과 (2026-08-03 실측)

| 항목 | 수 |
|---|---:|
| 색 상수 참조 `console_ui.py` | **343** |
| 색 상수 참조 `radar_core.py` | **160** |
| `setStyleSheet` 호출 | 88 (52 + 36) |
| `paintEvent` 내부 색 참조 | 26 (`ZoneStrip` 10 · `FacilityPlan` 16) |
| pyqtgraph 색 지정 | 약 20곳 / 위젯 5개 |

**감사에서 나온 결함 2건**

```
console_ui.py:505   pg.mkBrush(34, 211, 238, 150)   CYAN 의 RGB 를 숫자로 박음
radar_core.py:847   pg.mkBrush(0, 204, 255, 160)    #00CCFF — 팔레트에 없는 색
```

### 4-2. 방식

토큰을 중앙화하면 **`app.setStyleSheet()` 한 번으로 위젯 트리 전체가 재적용**된다. Qt 가 처리하므로
위젯마다 재스타일 메서드를 만들 필요가 없다. **재시작 불필요.**

QSS 로 커버되지 않는 곳만 따로 처리한다 — `paintEvent` 2곳(`update()` 호출로 재드로잉),
pyqtgraph 5위젯(§6 참조), `GLViewWidget` 1곳.

| 단계 | 작업 | 검증 |
|---|---|---|
| 1 | `theme.py` 신설 — 토큰 2벌 + 전역 QSS 템플릿 | import |
| 2 | 색 상수를 `radar_common.py` 에서 분리 (**젯슨 공용 파일. 젯슨은 색을 안 쓰므로 색 블록만 떼면 안전**) | `verify_jetson_safe.py` |
| 3 | 503개 참조 → 테마 객체 치환 (f-string 안이라 자동 치환 위험) | pyflakes + 4종 |
| 4 | `setStyleSheet` 88곳 → 전역 QSS + dynamic property (**10 Hz 재계산 문제도 여기서 같이 해결**) | 4종 |
| 5 | `paintEvent` · pyqtgraph · GL | 육안 |
| 6 | `QSettings` 저장·복원 + 설정 [디스플레이] 탭 | 재실행 유지 |

**레이아웃과 시그널/슬롯은 테마에 따라 바뀌지 않는다.** 두 테마가 같은 QWidget 구조를 공유한다.
페이지별·위젯별 QSS 를 두 벌 만들지 않는다.

### 4-3. 검증 — 6상태 × 2테마 × 2해상도 = 24장

상태: Normal / Warning / Critical / Acknowledged / Resolved / Radar disconnected
해상도: 1440×900 · 1920×1080
추가로 hover · disabled · selected 와 차트·포인트 클라우드·아이콘을 두 테마에서 각각 확인한다.
기존 4종(35·0 / 0건 / 64·0 / 16·0)도 그대로 통과해야 한다.

### 4-4. 규모 추정

**5~6세션.** 3·4단계가 대부분이다. 시간은 실제로 해봐야 안다.
**진짜 리스크는 시간이 아니라 누락이다** — 503개 중 놓친 하나는 라이트 모드에서
검은 배경 위 검은 글씨로 나타난다. 그래서 24장 캡처가 선택이 아니라 필수다.

### 4-5. 착수 시점 — 8/05(수) 젯슨 통합시험 이후

503곳을 건드린 뒤 실측하면 **끊김이 보였을 때 원인이 원래 구조인지 이 작업인지 가릴 수 없다.**
잠재 위험 3건이 미확인이고, 그중 하나가 바로 4단계에서 손댈 `10 Hz setStyleSheet` 다.
`CLAUDE.md` §11 — 외관보다 레이더 성능이 우선이다.

**범위는 리팩터링 + 회귀 검사다.** 503개 참조를 옮기는 것은 회귀 검사가 아니라 구조 변경이고,
회귀 검사는 그 뒤에 한다. 레이아웃 재설계는 하지 않는다.

## 5. 발표에 쓸 수 있는 것

- 멘토 지적 → **대비비 4.5:1 기준으로 팔레트를 재계산**했다는 서사. 색을 감으로 고르지 않았다는 근거가 된다.
- 숫자: 현행 CYAN 은 흰 배경에서 **1.81:1**(기준 4.5), 재계산 후 `#0E7490` **5.36:1**.
- **경보 중 테마 전환 차단** — 안전 시스템으로서의 설계 판단을 보여주는 항목.

## 6. 이 문서의 한계

- **대비비는 계산값이지 실측이 아니다.** 실제 관제실 조도·모니터 감마에서의 가독성은 확인하지 못했다.
- 라이트 팔레트로 실제 화면을 렌더해 본 적이 **없다.** 색 조합이 계산상 통과해도 화면에서 촌스럽거나 위계가 무너질 수 있다 — 적용 후 4해상도 스크린샷으로 재확인해야 한다.
- **`pg.setConfigOptions(background=PANEL, foreground=DIM)` 는 모듈 로드 시점에 1회 실행된다**(`radar_core.py:75`, `console_ui.py:2977`). 전역 설정이라 **이미 만들어진 위젯에는 반영되지 않는다.** 테마 전환 시 위젯별로 다시 지정해야 한다 — `SideView.plot.setBackground()`, `GraphPopup` 플롯 3개, `Track3D.gl.setBackgroundColor()`.
- 3D 포인트 클라우드(`Track3D`, pyqtgraph GL)의 색 반영은 실제로 시험해 보지 않았다.
