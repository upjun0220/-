## 1. 무엇이 문제인가

수행계획서는 MSDS를 5곳에서 SOP와 한 덩어리로 서술한다. 특히 p.7 산업안전 매뉴얼 표는 한 행을 통째로 할당했다 — *"사고 발생 구역의 물질 정보를 바탕으로 … 질산 누출 의심, 내산성 보호구 필수 착용 등 구체적 경고 생성"*.

현재 벡터DB는 PDF 13개 · 청크 634개 · 카테고리 5개(감전 4 · 협착 1 · 낙상 3 · 예지보전 3 · 위험성평가 2)이고 **물질안전보건자료가 0건**이다. 계획서 명시 항목의 미이행이다.

**단, 위험도는 README §C 기재보다 낮다.** §C는 "RAG REPORT 가 `POWER/MANPOWER/EQUIPMENT/MSDS` 4구획인데 칸만 있고 문서가 없다 → 할루시네이션 결함"이라고 썼는데, 8/10 작업본 `01_현행코드/` 전체에 `MSDS` · `MANPOWER` 문자열이 **존재하지 않는다**(`EQUIPMENT` 는 `facility.py` 의 설비 좌표 목록이라 무관). 화면에 빈칸이 떠 있는 결함이 아니라 **미구현 항목**이다.

> ⚠ 이 확인은 `console_ui.py` · `radar_core.py` · `radar_common.py` · `jetson_sender.py` 4개가 **미커밋 상태**(마지막 커밋 8/05)에서 이뤄졌다. README §F 가 경고한 조건이므로 커밋 후 재확인해야 한다. 다만 판단 근거가 행 번호가 아니라 **문자열 존재 여부**라 편집으로 뒤집힐 가능성은 낮다고 본다.

## 2. 대상 물질 3종과 실제 출처 — README 기재와 다르다

README §C 는 3종 전부 `msds.kosha.or.kr` 에서 받는다고 썼다. **절연유는 안 된다.**

| 물질 | 식별번호 | 실제 출처 | 근거 |
|---|---|---|---|
| SF6 (육불화황) | CAS 2551-62-4 · KE-32568 · UN 1080 | KOSHA MSDS 시스템 | 단일물질. 확인함 |
| 황산 | CAS 7664-93-9 · KE-32570 · UN 2796 | KOSHA MSDS 시스템 | 단일물질. 확인함 |
| 절연유(변압기유) | 해당 없음 | **제조사 제품MSDS** (S-OIL, HD현대오일뱅크 등 자사 사이트 공개 게시) | 광유계 혼합물이라 KOSHA 단일물질 20,568종에 없다 |

**황산은 농도를 반드시 명시한다.** 축전지실 전해액은 희석 황산(통상 30~37%)이고 100% 황산과 GHS 분류·응급조치가 다르다. 100% 황산 MSDS 만 넣으면 현장과 맞지 않는 지침이 검색된다. 유통 자료에 9% · 10% 등 농도별 MSDS 가 따로 있다.

## 3. 저작권 제약 — README 에 없던 항목

KOSHA MSDS 검색 페이지가 명시하고 있다.

> 안전보건공단에서 제공되는 MSDS는 **MSDS 작성과 검토 시 참고용으로만** 활용이 가능하며 …
> 공단의 MSDS는 **상업적 용도 등의 외부적인 용도로 사용하는 경우 저작권법 등 관련법규에 위배될 수 있음**을 알려드립니다.

README §C 는 "무료로 받을 수 있고"라고만 썼다. 무료 열람과 재배포 허용은 다르다. 본 프로젝트는 수행계획서 성과목표에 **특허출원·논문게재**가 있어 "외부적인 용도" 해당 여부가 애매하다.

**미확인이다. 법률 판단이 아니다.** 완화 경로 세 가지:

1. **공공데이터포털 오픈 API 사용** — `data.go.kr/data/15157612`(물질안전보건자료 조회 서비스), `15001197`(물질안전보건자료). 각 자료 페이지에 표기된 **공공누리 유형**을 따르면 이용 범위가 명시적으로 정해진다. 가장 안전한 경로로 보인다.
2. **제조사 제품MSDS 사용** — 산업안전보건법 제110·111조상 MSDS 제공은 제조·수입자의 **의무**이고 자사 사이트에 공개 게시된다. 절연유는 어차피 이 경로다.
3. **시연·연구 범위 한정** — 벡터DB를 배포물에 포함하지 않고 시연 환경에만 둔다. 발표자료에 출처를 명기한다.

권장: 1번 + 2번. 확정 전 공단 문의(042-869-0319)로 유권해석을 받는 것이 확실하다.

## 4. 다운로드 방법 (환경: **브라우저 — 사람이 직접**)

KOSHA MSDS 검색은 이용동의 체크 후 POST 로 도는 JS 화면이라 **자동 수집이 안 된다.** 3건뿐이므로 수동이 빠르다.

1. `https://msds.kosha.or.kr/MSDSInfo/kcic/msdssearchMsds.do` 접속
2. 이용 동의 체크
3. 검색조건 `CAS NO` 선택 → `2551-62-4` (SF6) 입력 → 검색 → 물질명 클릭 → PDF 저장
4. 같은 방식으로 `7664-93-9` (황산). 축전지 전해액 시나리오면 농도별 자료를 함께 확보
5. 절연유는 제조사 사이트(S-OIL `s-oil.com/energy/MSDS.aspx`, HD현대오일뱅크 `oilbank.co.kr/utillity/msds/`)에서 변압기유 제품 MSDS 저장

## 6. 미결 — 노출 방식

두 안이 충돌한다. **커밋 정리 후 결정한다.**

| 안 | 내용 | 장점 | 비용 |
|---|---|---|---|
| A. L4 질의 전용 | `06_MSDS` 를 적재만 하고 자동 경보 트리거를 붙이지 않는다. 근무자가 AI 질의로 물을 때만 검색된다 | 코드 수정이 사실상 없다. 감지 못 하는 사건을 감지하는 척하지 않는다 | 계획서의 "구체적 경고 생성"에 미달 |
| B. 감전 경보에 덧붙이기 | `감전 → 01_감전_LOTO + 06_MSDS` 로 카테고리를 덧붙인다(`stationary_anomaly` 가 두 카테고리에서 각 1건씩 뽑는 기존 구조와 동일) | 계획서 문구에 부합. 시연 임팩트 — `LOTO 절차를 따르시오` 에서 `이 구역은 SF6 사용 — 아크 분해생성물 유독, 진입 전 호흡보호구` 로 | `radar_common.py` 수정 → §5 검증 5종 + `verify_port.py` · `verify_jetson_safe.py` 재실행. 미커밋 4파일과 충돌 위험 |

**B 의 전제 조건:** 구역별 취급물질 매핑이 있어야 한다. 지금 `facility.py` 에 물질 필드가 없다. B 를 택하면 그 필드 추가가 선행이다.

레이더는 화학물질 누출을 감지할 수 없다(센서 없음). `EVENT_CATEGORY` 5개 어디에도 화학 사건이 없다. **A·B 어느 쪽이든 MSDS 는 감지 결과가 아니라 구역 속성으로만 붙는다.** 발표에서 "화학 누출을 감지한다"고 말하지 않는다.

- §1 의 코드 확인은 미커밋 상태에서 이뤄졌다. 커밋 후 `MSDS` 문자열 재검색이 필요하다.
