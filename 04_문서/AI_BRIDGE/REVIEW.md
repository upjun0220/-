# REVIEW — GPT ↔ Cowork 검토 왕복

> **여기만 대화형이다.** 결론이 안 나도 되고, 반박이 오가도 된다.
> **Claude Code 는 이 파일을 절대 읽지 않는다.** 여기 있는 것은 아직 지시가 아니다.
> 항목 수 제한 없음. 대신 **결론이 나면 아래로 옮기고 여기서 지운다.**
>
> | 결론 유형 | 옮길 곳 |
> |---|---|
> | 실행 요청 | `INBOX.md` |
> | 설계 결정 | `04_문서/` ADR |
> | 언젠가 할 이슈 | `BACKLOG.md` |
> | 기각 | 지운다 (기각 사유가 남길 가치가 있으면 ADR 에 한 줄) |
>
> **`OUTBOX.md` 는 GPT 도 읽어도 된다** — Claude Code 가 낸 질문에 답하는 건 유효하다.
> 단 답은 OUTBOX 에 쓰지 말고 여기나 `INBOX.md` 에 쓴다. OUTBOX 는 Claude Code 전용 발신함이다.

## 형식

```
### RV-001  제목
- 제기: GPT | Cowork | 사용자
- 상태: 논의중 | 합의 | 기각
검토 내용. 반대 의견이 있으면 근거와 함께.
→ 결론: (나면 여기에. 그리고 옮기고 지운다)
```

## 열린 항목

### RV-001  GPT 가 INBOX/OUTBOX 를 채팅창처럼 사용하는 방식
- 제기: GPT
- 상태: 기각 — 대안 채택
INBOX/OUTBOX 는 triage 대상이라 "이동 후 삭제 · 최대 10개 · 완료 로그 금지" 규칙이 걸려 있다.
채팅으로 쓰면 항목이 쌓여 `validate_ai_bridge.py` 가 매번 NG 를 낸다.
그리고 GPT → INBOX → Claude Code 직통이면 **triage 가 사라진다** — 8/03 검토에서 걸러낸
6건(Advisory 등급, 중복 문서 2개, `docs/` 위치, 기존 문서 중복 작성, 안전 제약 분리)이 그대로 갔을 것이다.
→ 결론: 이 파일(REVIEW.md)을 신설한다. GPT 는 여기에 쓰고, 합의된 것만 INBOX/ADR/BACKLOG 로 간다.

### RV-002  젯슨 연결 전 먼저 고칠 결정적 결함 4건과 환경 복구 1건
- 제기: GPT
- 상태: 논의중
README와 `01_현행코드/`의 수신→상태기계→표시 경로를 대조하고, 데모 UI와 실측 재생 화면을 직접 실행했다.
UTF-8 환경에서는 pyflakes 경고 0, v1 결함 35항목 0건, 레이아웃 0건, 실데이터 재생 64항목 0건,
평면도 흐름 16항목 0건이다. 하지만 자동검사가 놓친 결정적 표시 결함과 내일 검증을 막는 환경 문제가 남아 있다.

**Claude 판단에 대한 반박.** `HANDOFF.md`는 젯슨 통합시험을 먼저 하고 RED 두 곳만 고치도록 했지만,
실물 부하가 있어야 판단할 성능 문제와 로컬에서 이미 결정적으로 재현된 결함을 한데 묶어 미룰 이유는 없다.
아래 1~4는 범위가 좁고 젯슨 판정 경로를 건드리지 않으며, 오늘 회귀검사로 증명할 수 있다.
오히려 그대로 실물 시험에 들어가면 센서 문제와 이미 아는 UI 거짓 표시가 한 화면에 섞여 원인 분리가 어려워진다.

1. **주의 경보 제목이 빨강으로 고정된다.** 정지형·진동 배너와 본 패널은 주황인데
   `SopView.__init__`와 `EvidenceView.set_event`가 `RED`를 고정해 드로어 제목만 빨강이다.
   `sev_color(sev)`로 통일하고 warning/critical 렌더를 직접 확인해야 한다.
2. **경보 첫 프레임의 `hide_shape`가 약 100 ms 늦는다.** Claude가 상태기계를 그리기 앞으로 옮겼지만
   `on_alert`는 이동 전에 계산한 값을 계속 쓴다. 즉 주석의 주장과 실제 변수가 어긋난다.
   `_pump_state(pkt)` 뒤 경보 상태를 다시 읽고, 첫 패킷에서 형상이 즉시 숨는 회귀검사를 추가해야 한다.
3. **기존 차단을 현재 사건의 자동 차단처럼 말한다.** 낙상으로 차단기가 이미 내려간 뒤 warning 사건이 오면
   `_set_auto_action()`은 `breaker.state`만 보고 "차단 신호 발신"이라고 쓴다. 패킷에는 `breaker.reason`이 있으므로
   현재 사건과 차단 사유가 같은지 구분해 "기존 차단 상태"와 "이번 사건의 차단"을 다르게 표시해야 한다.
4. **문서의 검증 명령이 Windows 기본 cp949 콘솔에서 실패한다.** 첫 검사 출력의 `—`에서
   `UnicodeEncodeError`가 발생해 중간 종료됐다. `$env:PYTHONUTF8='1'`에서는 전부 통과했지만,
   운영 절차가 숨은 환경변수에 의존하면 내일 같은 실패가 반복된다. 검증 진입점에서 UTF-8 출력을 보장해야 한다.
5. **SOP DB가 꺼져 있다.** Ollama의 `gemma2:2b`, `bge-m3`는 설치돼 있지만 `radar-guard-db`는
   43시간째 `Exited (0)`이고 `sop_doctor.py`는 접속 실패다. 코드 변경이 아니라 사전 환경 복구 항목으로 처리한다.

**GPT 제안 우선순위:** 1→2→3→4를 최소 수정하고 UI 전체 검증을 다시 실행한 뒤 5를 복구해
`sop_doctor.py`로 실제 검색을 확인한다. 10 Hz 렌더 최적화, stale 베일 정책, 테마 전환,
LangChain 마이그레이션은 실물 수치나 별도 결정이 필요하므로 지금 섞지 않는다.
→ 결론: 사용자 승인으로 REVIEW 상정. Cowork의 반박·대안 검토 후 실행 요청만 INBOX로 옮긴다.
