# 시연 런북 (2026-08-20)

- 대상: 시연 진행자
- 전제: PHASE 1(경보 latch 구조) · PHASE 2(감전·협착) 배포 완료
- 미보유: INA226 #2(접지선 누설) — **감전 "확정" 시연은 불가**. 아래 §5 참조

---

## A. 시연 전 검증 — 관객 없이, 약 30분

여기서 하나라도 NG 면 시연에 들어가지 않는다.

### A-0. 기동 순서 (틀리면 파서가 죽는다)

1. 젯슨 재부팅
2. **레이더(IWR6843) 먼저 연결** — CLI `/dev/ttyUSB0`, DATA `/dev/ttyUSB1`
3. **약 5초 기다린 뒤** 차단기(CH340) 연결 — `/dev/ttyUSB2`
4. `ls /dev/ttyUSB*` 로 세 개가 위 순서대로 잡혔는지 확인

⚠ 차단기를 먼저 꽂으면 CH340 이 `ttyUSB0` 을 차지해 레이더가 밀리고 파서가 실패한다.
   USB 오류 `-32` / `-110` / `Errno 5` 가 뜨면 프로세스 재시작으로 복구되지 않는다.
   젯슨을 재부팅하고 2번부터 다시 한다.

5. 노트북·젯슨을 **휴대폰 핫스팟**에 연결. 학교 Wi-Fi 는 단말 간 통신이 차단된다
6. 젯슨 IP 확인 → 노트북 UI 기동 시 그 IP 를 쓴다

### A-1. 기동 로그 확인

젯슨 stdout 앞부분에서 아래 네 줄을 눈으로 본다.

| 확인할 줄 | 정상 |
|---|---|
| `[RF]` | `fall_classifier 로드 OK` |
| `[RF30]` | `용도분리 모델 로드 OK (window=30 ...)` |
| `DEVICE` | `cuda` |
| `[HAZARD]` | `Zone A = 'electric'` (또는 의도한 모드) |

`[RF30] 모델 없음` 이면 낙상 검출률이 크게 떨어진다. 배포를 다시 확인한다.

### A-2. 처리율 — 이번 시연의 최대 위험

입실 상태로 20초 두고 젯슨에서 측정한다.

```
for i in $(seq 1 20); do
  P=$(tail -c 300000 /home/project/stage1_filtered.json | grep -o '"frame_num":[ ]*[0-9]*' | tail -1 | grep -o '[0-9]*$')
  S=$(tail -1 /home/project/clf_decisions.jsonl | grep -o '"fnum_last":[ ]*[0-9]*' | grep -o '[0-9]*$')
  echo "$(date +%H:%M:%S) parser=$P sender=$S diff=$((P-S))"
  sleep 1
done
```

| 판정 | 기준 |
|---|---|
| **합격** | `diff` 가 증가하지 않고 0 근처 유지 |
| **불합격** | `diff` 가 계속 커진다 → 밀림 재발. 시연하면 경보가 갈수록 늦게 뜬다 |

`clf_decisions.jsonl` 최근 200건의 `dt` 중앙값도 본다. **0.063~0.08초** 여야 한다.
`dt` 최대값에 0.657초 스파이크가 있으면 Modbus 블로킹이 남은 것이다.

### A-3. 낙상 지연 — 60초로 시험한다

**입실 → 60초 대기 → 낙상.** 30초로 시험하면 의미가 없다.
지금까지 지연이 입실 시간에 비례해왔기 때문이다.

- 합격: 경보까지 **2초 이내**
- 낙상 실제 시각을 노트북 시계로 적어 화면 표의 `시각` 과 비교한다

### A-4. 배타 latch 동작

1. 낙상 경보를 띄운다
2. **'상황 종료' 를 누르지 않은 채** 다시 낙상한다 → **안 떠야 정상**
3. 젯슨 로그에 `기존 fall_detected 경보 유지(배타 latch)` 가 남았는지 확인
4. '상황 종료' 를 누르고 다시 낙상 → 정상 latch

⚠ 3번이 안 남으면 무음 유실이다. 시연 전에 고쳐야 한다.

### A-5. 차단기 응답

`grep -c "BREAKER ERROR" <젯슨 로그>` 로 시연 구간 발생 건수를 센다.
0 이면 정상. 계속 뜨면 **화면 경보와 실제 차단이 다르다** — 시연 중
"차단 신호 발신 · 릴레이 응답 없음" 이 뜰 것이고, 그건 정직하게 설명한다.

### A-6. 차단 범위 실측 (8/20 확정 — 작업 대상 설비 회로 1개)

차단 상태에서 노트북 UI(또는 젯슨 패킷)의 INA226 표시가
**`0.000A` / 약 `12.1V`** 인지 확인한다. 로직 전원은 살아 있고(전압 정상),
부하 전류만 0이어야 한다 — 릴레이 CH0 밖(조명·비상등)까지 끊는 게 아니라는
실측 증거다. 값이 다르면 배선이 릴레이 앞단에 물린 것이다(§설계 ADR §7 참조).

## B. 시연 순서

`--hazard` 전환은 sender 재기동이 필요하다. **모드 전환은 한 번만** 하도록 묶는다.

```
[1부] --hazard electric 로 기동
        시나리오 1. 낙상
        시나리오 2. 감전 의심

[2부] sender 재기동 --hazard pinch
        시나리오 3. 협착
```

### 시나리오 사이에 반드시

**'상황 종료' 를 누른다.** critical 이 떠 있으면 다음 사건이 뜨지 않는다.
이건 결함이 아니라 설계다 — 아래 §D 에서 설명 문구를 준다.

---

### 시나리오 1 — 낙상

| 단계 | 동작 | 화면에서 볼 것 |
|---|---|---|
| 1 | 입실 버튼 | 재실 상태 전환, 3D 에 점군 |
| 2 | ROI 안에서 자연스럽게 움직임 | 점군 추적 |
| 3 | **낙상** | **2초 이내 빨강 '낙상' critical** |
| 4 | — | 판단 근거 카드 — 도플러 피크·높이 변화·RF 점수 |
| 5 | '상황 종료' | 표에 종료 시각 기록 |

**말할 것**
> 레이더가 판정하고 젯슨이 차단합니다. 노트북이 죽어도 차단은 이미 일어난 뒤입니다.
> 화면에 보이는 것은 판정 결과이지 판정 그 자체가 아닙니다.

**근거 카드를 반드시 짚는다.** 이게 "그래프만 그리는 시스템" 과 갈리는 지점이다.

---

### 시나리오 2 — 감전 의심 (정지형 유래)

`--hazard electric` 모드에서 동작한다.

| 단계 | 동작 | 화면 | 경과 |
|---|---|---|---|
| 1 | 입실 | 재실 | — |
| 2 | ROI 안에서 **정지** | — | 0초 |
| 3 | 계속 정지 | **PRE-ALERT 배너** "no-motion 10s" | **10초** |
| 4 | 계속 정지 | **주황 '감전 의심' warning** | **20초** |
| 5 | (차단기 동작 시) | **빨강 critical 승격 · "설비 차단됨"** | — |
| 6 | '상황 종료' | 종료 기록 | — |

**10~20초 사이를 대사로 채운다.**
> 지금 10초 무동작으로 사전경보가 떴습니다. 아직 경보가 아니라 경고입니다.
> 20초까지 움직임이 없으면 위험경보로 올라갑니다.
> 작업자가 움직이면 타이머가 초기화됩니다.

**말할 것 — 이게 이 시연의 핵심**
> 감전을 판정하는 것은 레이더가 아닙니다. 레이더가 답하는 것은 두 가지입니다 —
> **그 순간 거기 사람이 있었는가**, 그리고 **그 사람이 지금 움직이는가.**
>
> 기존 누전차단기는 "전기를 끊었다" 만 알지 **왜 끊겼는지를 모릅니다.**
> 설비 절연 불량인지 사람이 만진 건지 구분하지 못합니다.
> 그것이 우리가 레이더를 붙인 이유입니다.

**보조 시연 — 인명 무관 (여유가 있으면)**
퇴실 버튼을 누른 상태에서 차단기를 내리면 **경보가 뜨지 않고**
"차단됨 · 인명 무관(설비 고장 의심)" 만 표시된다.
> 같은 차단인데 사람이 없으면 인명사고로 부르지 않습니다. 이 구분이 우리 시스템입니다.

---

### 시나리오 3 — 협착

sender 를 `--hazard pinch` 로 재기동한 뒤 진행한다.
동작은 시나리오 2 와 같고 **이름만 '협착 · 끼임'** 으로 바뀐다.

기동 로그에 `[HAZARD] Zone A = 'pinch'` 가 찍혔는지 먼저 확인한다.

**말할 것**
> 사고 이름은 센서가 추론하지 않습니다. **사전에 등록된 위험구역이 규정합니다.**
> 구역 설정은 원인 센서가 아니라 시설 위험성평가에서 온 정책 입력입니다.
> 인증된 상용 안전 레이더와 같은 계열입니다.

## C. 실패 시 대응

| 증상 | 원인 | 대응 |
|---|---|---|
| 낙상이 늦게 뜬다(5초 이상) | 프레임 밀림 재발 | sender 재시작. 재시작하면 백로그가 0 이 된다 |
| 낙상이 아예 안 뜬다 | 이전 경보가 latch 중 | **'상황 종료' 를 눌렀는지 확인.** 이게 가장 흔한 원인 |
| `[RF30] 모델 없음` | 배포 누락 | 젯슨 `~/fall_classifier_hybrid30.joblib` 존재 확인 |
| 3D 가 안 움직인다 | UDP 미수신 | 핫스팟 연결·방화벽 5005 확인. 젯슨 IP 재확인 |
| "차단 신호 발신 · 릴레이 응답 없음" | Modbus 무응답 | **정직하게 설명한다.** §D 참조 |
| 파서 실패 / USB 오류 | 연결 순서 | 젯슨 재부팅 → 레이더 먼저 → 5초 → 차단기 |

**시연 중 코드를 고치지 않는다.** 위 대응으로 안 되면 그 시나리오를 건너뛴다.

## D. 질문 대비 — 미리 준비한 답

**"낙상에 전원 끊는 건 과하지 않나요?"**
> 차단 대상은 작업 대상 설비 회로 1개입니다(본 시연은 LED 부하로 모의).
> 원인이 아직 확정되지 않은 상태에서 가장 가까운 에너지원을 격리하는 것이
> LOTO의 기본 원칙이고, 비용이 설비 1개 정지로 제한되므로 격리를 선택합니다.
> 조명·비상등·통신 같은 다른 안전 설비는 이 회로 밖입니다.

**"경보가 하나 떠 있으면 다른 사고는 안 뜨나요?"**
> 그렇습니다. 한 구역 한 작업자 스코프이고, 경보가 뜨면 운영자가 이미 그 구역으로
> 갑니다. 확인하고 종료해야 시스템이 다음 사건을 봅니다. 의도된 동작이고
> 한계로 문서에 적어뒀습니다. 다만 판정과 기록은 계속 돌아서, 그 사이에 무엇이
> 있었는지는 로그에 전부 남습니다.

**"감전을 어떻게 검출하나요?"** (센서 도착 전)
> 지금 보신 것은 **감전 시나리오 판정 논리의 검증**입니다.
> 레이더로 감전 자체를 판정하는 것은 물리적으로 불가능합니다 —
> 근육 강직은 전원 주파수 60Hz 인데 프레임레이트가 10fps 라 나이퀴스트 한계가 5Hz 입니다.
> 감전을 판정하는 것은 누설전류이고, 접지선 전용 계측기를 추가하는 것이 다음 단계입니다.
> 임계는 인체 보호용 누전차단기 국제 기준과 같은 30mA 입니다.
> **아키텍처는 그대로이고 트리거 신호원만 교체됩니다.**

**"과전류로 감전을 잡는 건가요?"**
> 아닙니다. 인체 저항이 1~2kΩ 이라 220V 에서 100~200mA 가 흐르는데,
> 과전류 차단기 정격은 15~30A 입니다. **과전류로는 감전을 못 잡습니다.**
> 그래서 누설전류로 가는 것이고, 지금 전기 계측은 **등급을 올리는 보조 신호**입니다.

**"차단기가 응답을 안 하는데요?"**
> 화면 경보와 실제 차단은 다른 사건이고, 그래서 따로 표시합니다.
> 지금 보이는 것은 판정이 정상이고 릴레이 통신이 미해결이라는 뜻입니다.
> 이걸 같은 것으로 보여주지 않는 것이 안전 시스템의 기본입니다.

**"차단까지 몇 초 걸리나요?"**
> 소프트 판단 → Modbus → 원격 분합은 **초 단위**입니다.
> 단락·누전 순시보호는 차단기 자체 하드웨어 몫이고, 저희 융합의 가치는
> **예지와 조기 경보**입니다. "0.1초 차단" 이라고 말하지 않습니다.

**"두 위험구역을 동시에 구분하나요?"**
> 아닙니다. 관측 영역이 1.44m 정사각형인데 방위 분해능 28° 에서 위치 오차가
> 0.65~1.15m 라 그 안을 나누면 오차가 구역보다 커집니다.
> **동시 구분을 주장하지 않고** 구역 타입을 전환해 시나리오를 하나씩 보여드립니다.

## E. 말하지 말 것

- "실제 감전을 검출합니다" → 센서 도착 전에는 성립하지 않는다
- "0.1초 안에 차단합니다" → 소프트 경로는 초 단위다
- "실배전의 지락과 토폴로지가 같습니다" → 왕복 불균형이 없어 과장이다
- "감전과 협착을 동시에 구분합니다" → 위치 오차가 구역보다 크다
- "낙상을 100% 잡습니다" → 젯슨 재학습본 재현율 70.0%, E 는 1/10 이다
- "과전류(overcurrent)로 이상을 시연합니다" → 시나리오에 없다. LED 부하 실측
  `0.116A` 로는 `CURR_LIMIT=1.5A` 를 넘길 물리적 방법이 없다
