# Radar-Guard 진행 보고 — 6/6 중간회의 이후 (~2026-07-02)

> 출처: 공모전 폴더 `README.md` 개발 로그(실측 기반, 2026-06-29~07-02 기록). 아래는 지난 중간회의(6/6) 시점 WBS 대비 달라진 부분만 원인→결과 구조로 정리.

## 한 줄 요약

6/6 시점엔 전부 목데이터 기반 프로토타입이었음. 이후 실제 레이더를 천장에 설치해 실측 데이터를 모았고, 그 과정에서 설계 가정 두 개가 틀린 게 드러나 판별 로직과 RAG 구조를 실측 기준으로 다시 짰음. 낙상 감지는 라이브에서 확실히 됨(10/10). 남은 문제는 보행·정지자세(감전/협착) 오탐 처리.

## 1. 하드웨어를 실제로 붙이면서 시작된 변화

**원인**: 6/6까지는 레이더 없이 목데이터로만 검증했음. Phase 8부터 실제 TI IWR6843ISK-ODS 레이더를 연결.
**결과**: 6/29 최초 연결 시 포트 문제로 데이터 0바이트 → 6/30 펌웨어 재플래싱(UniFlash)으로 Point Cloud 수신 확인 → 7/2까지 레이더 완전 고정 후 낙상/빠른앉기/보행/정상 각 10개, 협착/감전 각 5개 = **실측 50샘플** 수집 완료.

## 2. 설치 방식 변경: 측면 → 천장 오버헤드

**원인**: 산업현장 특성상 기계·설비에 의한 가림(occlusion)이 크고, 사용 중인 IWR6843ISK-**ODS**가 애초에 오버헤드용으로 설계됨. 또 낙상 시 낙하 방향이 천장 센서 시선과 일치해 도플러 신호가 강해짐.
**결과**: 설치를 천장으로 확정(스코프: Zone당 1명, 다인원 추적은 이후 과제). 좌표계 전체를 `height = 2.30m(천장고) − y(range)` 기준으로 변경 → 화면 좌표, classify 로직 등 아래 항목들이 전부 이 변경에 연쇄적으로 영향받음.

## 3. UI가 자꾸 멈추던 문제 — 원인 특정 후 해결

**원인**: `add_log()` 내부에서 `threading.Lock()`을 거는데, 파이프라인이 학습 완료(TRAINING→LIVE 전환) 시점에 이미 같은 락을 쥔 채로 `add_log`를 다시 호출 → 같은 스레드가 자기 락에 걸려 파이프라인·렌더 스레드가 동시 정지(비재진입 락 데드락). JSON 처리나 렌더링 자체는 원인이 아니었음.
**결과**: `Lock` → `RLock`(재진입 허용)으로 교체하고 해당 호출을 락 밖으로 이동. Warmup 완료 직후 멈추던 현상이 없어지고 TRAINING→LIVE가 정상 동작하게 됨(7/1).

## 4. 낙상 판별 기준 전면 교체 — "높이"가 아니라 "도플러"

**원인**: 기존 판별 로직(측면 설치 + 목데이터 기준)은 `z_vel`, 절대 높이 등을 썼는데, 천장에서 실측해보니 쓰러진 사람도 centroid 높이가 ~1.4m로 유지되어 **높이 기반 판별이 아예 작동하지 않음**을 실측으로 확인.
**결과**: 낙상 판별을 "도플러 격렬함(`dop_std` 피크 ≥ 1.2)" 기준으로 전면 재작성(50샘플 기반, 낙상 1.29~1.88 / 나머지 ≤1.16으로 명확히 분리). **라이브 재검증 결과 낙상 10/10 확실히 감지.** 감전·협착은 실측으로 신뢰성 있게 구분이 안 돼 `stationary_anomaly`(정지형 이상)로 통합, human-in-the-loop 경보로 처리.

## 5. RAG 구조 변경: 생성형(LLM) → 검색 전용

**원인**: 젯슨에서 이벤트마다 `llama3:8b`(생성 LLM, 8B)를 돌리면 메모리/연산이 고갈(OOM)되어 **시스템 전체가 멈춤**(마우스·원격 조작 불가)을 확인.
**결과**: `llama3:8b`를 실시간 경로에서 제거. 현재는 `nomic-embed-text`(임베딩 전용 소형 모델)로 상황을 벡터화 → pgvector 검색 → 매뉴얼 원문을 그대로 화면에 표시하는 **검색 전용** 구조로 전환. 대신 이벤트 발생 즉시 하드코딩된 1차 조치를 먼저 보여주고, 발표용으로 다듬은 문장이 필요하면 젯슨이 아닌 PC에서 8B로 별도 생성하는 방식 채택. (WBS 원래 항목 "Ollama → Jetson 모델 이식(Llama3 전환)"은 형태를 바꿔 완료 처리 — 아래 WBS 참고)

## 6. 안전 로직 강화 (경보 처리 방식 변경)

**원인**: 넘어진 사람은 쓰러진 채 가만히 있는 게 정상 상태라, 기존처럼 "정상 프레임이 이어지면 자동 해제"하는 로직은 낙상을 "해결됨"으로 오판함.
**결과**: 자동 해제를 없애고 **경보 latch + 수동 [Event Resolved] 버튼**으로 변경(산업 안전 표준에 맞춤). 부수적으로 **Incident History 패널**(감지시각·유형·존·해제여부 기록), **Motion/Vibration 패널**(dop_std 실시간 + 낙상 문턱선 시각화), **즉시조치(instant SOP)** 표시를 함께 추가.

## 7. 남은 문제 — 보행/정지자세 오탐, 3차례 원인 규명·패치 (7/2 하루 동안)

**원인 1 (보행→진동 오탐)**: 수집 때 측정한 보행 포인트 수(n)가 라이브 환경보다 높게 나와, 라이브에선 "n≥18=정상" 조건을 못 타고 진동 판정(dop_std≥0.40)에 걸림. 또 걷다가 앉는 등 동작이 섞인 전이 구간이 오판을 늘림.
**결과**: `n_mean≥18` → `n_p75≥15`(상위 25%값 사용, 전이구간에 강함)로 변경, 진동 판정을 "전반부·후반부 둘 다 지속" 조건으로 강화, non-fall 경보는 3연속 판정이어야 latch되도록 변경. 오프라인 재검증에서 원본 50샘플 유지 + 전이 창 2,000회 오탐 0건 확인. **라이브 재검증은 아직 필요.**

**원인 2 (정지형/감전·협착 미검출)**: 판정 로그(`clf_decisions.jsonl` 68건) 분석 결과, 라이브에서 협착 자세의 포인트 수(n 4.2~6.7)가 수집 때(9.7~13)보다 낮게 잡혀 stationary 조건의 하한(n≥8)을 못 넘김. n 하한을 낮추면 가만히 서 있는 정상 상태와 구분이 안 됨(feature상 거의 동일).
**결과**: 문턱 조정 대신 **Zone + 지속시간 게이트**로 설계 자체를 변경 — 위험 Zone 안에서 저동작 15초 지속 시 1차 PRE-ALERT(움직이면 자동 취소), 30초 지속 시 2차 stationary 경보(latch). 상용 lone-worker 장비의 "무동작 타이머 + pre-alert 단계"와 같은 방식. `MAINT_MODE`(계획 정비 중 억제) 플래그도 함께 추가. 구현 완료, 라이브 검증 필요.

**원인 3 (사람 떨기로 진동 데모 시도)**: 사람이 제자리에서 떠는 동작의 도플러(0.30~0.42)가 오히려 걷기(0.43~0.51)보다 낮게 나와, 문턱을 어디에 두든 떨기를 잡으면 걷기도 같이 잡힘 — 천장 레이더가 수직 속도만 민감하게 잡는 물리적 한계.
**결과**: **사람 떨기 기반 진동 데모는 폐기.** 대신 실제 진동원(선풍기)으로 10샘플을 새로 수집해 진동 문턱을 확정하기로 결정. `radar_collect.py`에 `VIB(machine)` 버튼 추가 완료, 다음 실측 세션에서 수집 예정.
