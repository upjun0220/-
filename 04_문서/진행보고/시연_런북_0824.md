## 0. 이번 시연에서 보여주는 것과 보여주지 않는 것

먼저 정하고 시작한다. 경계가 흐려지면 질문 하나에 무너진다.

| 보여준다 | 보여주지 않는다 |
|---|---|
| 낙상 확정 → 경보 · SOP (전원 차단 없음) | 낙상 → 전원 차단 (설계상 제외) |
| 과전류 확정 → 작업 대상 설비 회로 차단 | 감전 · 누설전류 (INA226 #2 미도착) |
| 차단 후 5초 무동작 → 협착 확정 | 일반화된 협착 동작 인식 (B 4/10 · C 1/10) |
| 차단 후 2초 PINCH 모션 → 협착 확정 (시연자 A 한정) | 서서 팔만 끼인 협착 |
| 차단 후 걷기 → 협착 뜨지 않음 | 정지형 이상 단독 경보 (협착 게이트로 용도 변경) |
| 수동 3중 확인 복구 (자동 복구 없음) | 산업 설비 과전류 보호 (8V 모의회로 전용) |

**협착 Shadow 는 화면에 아무것도 띄우지 않는다.** 심사위원에게 설명할 대상이 아니라
로그로만 남는 계측이다. 질문을 받으면 그때 답한다(6절 Q4).

## 1. 사전 점검 — 시연 30분 전

### A-0. 전원 순서 (틀리면 시작하자마자 차단된다)

**파워서플라이를 먼저 켜고, 그 다음에 sender 를 LIVE 로 올린다.**

`VOLT_MIN = 7.50` 이고 판정 게이트가 `_live = state['phase'] == PH_LIVE` 다.
입실 여부와 무관하다. 전원이 꺼진 상태에서 LIVE 로 들어가면
`volt ≈ 0 < 7.50` → `voltage_drop` critical → 2초 뒤 차단된다.

| 순서 | 동작 | 확인 |
|---|---|---|
| 1 | 파워서플라이 ON (8V, 전류제한 0.25~0.30A) | 출력 표시 |
| 2 | 릴레이 · INA226 전원 확인 | LED 점등 |
| 3 | 젯슨 `radar_parser.py` → `jetson_sender.py` 기동 | 프로세스 2개 |
| 4 | LIVE 진입 | `phase=LIVE` |

### A-1. 기동 로그 확인

```
[PROFILE] / [POWER] CURR_LIMIT=0.10A · VOLT_MIN=7.50V
[RF] fall_classifier 로드 OK
[RF30] 용도분리 모델 로드 OK
Device: cuda
```

`CURR_LIMIT` 이 `1.5` 로 나오면 구 배포본이다. 즉시 중단하고 재배포한다.

### A-2. Modbus · INA226 readback

HELLO 조회 1건으로 아래를 전부 확인한다.

| 항목 | 기대값 |
|---|---|
| `breaker.connected` | `true` |
| `breaker.src` | `modbus` |
| `breaker.error` | `null` |
| `breaker.state.A` | `ON` |
| `power.connected` | `true` |
| `power.volt` | 7.9 ~ 8.1 V |
| `power.curr` | 0.0020 ~ 0.0035 A |

`INA226 0x40 ERROR` 가 매초 찍히면 2번째 INA226 을 찾는 것이다. 이번 시연에는
없으므로 무시해도 되지만, 로그가 지저분해지므로 가능하면 비활성화하고 간다.

### A-2b. 시연자를 A 로 고정한다 (협착 PINCH 경로)

협착 PINCH 판정(`ds_mean>0.33` · `ds_max<=0.59` · `height_mean<=0.83`, 20프레임 롤링)은
**시연자 A 의 고정 연기에 맞춰 정한 시연 전용 규칙**이다. 일반화 규칙이 아니다.

| 라벨 | A | B | C |
|---|---|---|---|
| PINCH 재현 | 7~8/10 | 5/10 | 1/10 |
| 정지(still) 오탐 | 0/10 | 6/10 | 9/10 |

시연자가 A 가 아니면 **협착은 거의 안 뜨고 가만히 서 있을 때 뜬다.** 반드시 A 가 한다.
A 가 못 하면 협착 PINCH 시나리오(시나리오 2의 모션 경로)를 빼고 5초 무동작 경로만 쓴다.

### A-3. 배선 육안 확인

- 릴레이 CH0(CH1 채널) 부하 = **LED + 50Ω 저항 분기뿐**
- 조명 · 비상등 · 노트북 전원은 CH0 밖
- 시험 스위치가 **해제 상태**

### A-4. 낙상 지연 실측 — 아직 검증되지 않은 항목

**이것이 이번 사전점검의 핵심이다.** 8/19 낙상 미검출의 원인이었던 처리율 문제가
실제로 해결됐는지 배포본에서 확인한 적이 없다.

1. 입실 후 **60초 이상** 경과시킨다 (백로그가 쌓일 시간을 준다)
2. 낙상 1회
3. 화면에 낙상 critical 이 **2초 이내** 뜨는지 본다

| 검사 | 합격 |
|---|---|
| 낙상 표시 지연 | 2.0초 이내 |
| `[TIMING]` 프레임당 총 | 63 ms 이하 |
| `clf_decisions.jsonl` `dt` 중앙값 | 0.063 ~ 0.08 s (0.657 s 스파이크 없음) |
| parser/sender `frame_num` 격차 | 증가하지 않음 |

**불합격이면 시연을 진행하지 않는다.** 낙상이 늦게 뜨는 시연은 안 하느니만 못하다.

### A-5. Shadow 로그 준비

## 2. 리허설 — Shadow 데이터 수집 (비공개, 심사 전)

Shadow 는 **협착 동작을 실제로 해봐야** 의미가 있다. 본 시연에는 그 구간이 없으므로
리허설에서 따로 받는다.

### 왜 따로 하는가

Shadow 로그에는 라벨 필드가 없다. `ts` 와 계측값만 있다.
그래서 **한 번의 차단 사이클에 한 가지 동작만 한다.** 그러면 그 사이클의
모든 로그 줄이 같은 라벨이 되어 사후에 나눌 수 있다.

### 사이클 절차 (1회 약 40초)

```
입실 → 스위치 누름 → (2초) 차단 확인 → [동작 X를 15초간] → 스위치 해제
     → Event Resolved → CMD_RESTORE 3중 확인 → 다음 사이클
```

Shadow 는 3초마다 1줄을 쓰므로 15초면 사이클당 약 4~5줄이 남는다.

### 받을 동작과 횟수

| 동작 | 라벨 | 횟수 | 설명 |
|---|---|---:|---|
| 제자리 발버둥 (서서) | pinch-stand | 5 | 팔·상체를 크게 흔들되 발은 안 옮긴다 |
| 제자리 발버둥 (쭈그려) | pinch-crouch | 5 | 낮은 자세로 몸부림 |
| ROI 내 걷기 | walk | 5 | 왕복하며 계속 걷는다 |
| 설비 확인 동작 | inspect | 3 | 쭈그려 앉아 살펴보고 손 뻗기 |
| 완전 정지 | still | 3 | 대조군 (협착 critical 이 뜨는 것을 확인) |

**총 21 사이클 · 약 15분.** 사이클마다 시작 시각과 라벨을 종이에 적는다.

### 무엇을 얻는가

로그의 `net_displacement` · `path_length` · `x_range` · `z_range` 로
**"제자리인가"** 를 실제로 잴 수 있는지 확인한다. 이게 되면 협착 동작 판정에
RF 가 필요 없어진다. 안 되면 위치 정확도(cross-range 오차 0.65~1.15 m)가
ROI 1.44 m 안에서 부족하다는 결론이 나온다. 어느 쪽이든 숫자가 남는다.

⚠ 로그의 `candidate` 태그는 `dop_mean ≥ 0.38 · height_mean ≤ 1.00 · n_mean ≤ 18.0`
탐색 문턱이다. `height_mean ≤ 1.00` 때문에 **서서 하는 발버둥은 candidate=False 로
찍힌다.** 태그를 믿지 말고 원시 계측값으로 판단한다.

## 3. 본 시연 — 시나리오 3개

전체 6~8분. 순서를 바꾸지 않는다. 낙상은 차단을 안 하므로 릴레이를 건드리지 않아
가장 먼저 하는 것이 깨끗하다.

### 시나리오 1 — 낙상 (약 90초)

| 시각 | 동작 | 화면 |
|---|---|---|
| 0:00 | 입실 버튼 | `occupied=true` |
| 0:05 | ROI 안에서 정상 작업 동작 | 정상 |
| 1:05 | **낙상** (60초 이상 경과 후) | 낙상 critical + SOP 카드 |
| 1:10 | LED 확인 | **켜져 있다** |

**말할 것:** "낙상이 확정됐지만 전원은 끊지 않습니다. 낙상은 신체 사고이지
전기 위험을 증명하지 않습니다. 구조 접근이 우선이고, 자동 차단은 전기·협착
사건에만 적용합니다."

LED 가 계속 켜져 있는 것이 **의도된 동작**이라는 걸 먼저 말해야 한다.
안 그러면 고장으로 보인다.

→ `Event Resolved` 를 누른다. (누르지 않으면 다음 사고가 같은 `ev_id` 에
   병합되어 별개 사고로 안 보인다.)

### 시나리오 2 — 과전류 → 협착 (약 90초)

| 시각 | 동작 | 전류 | 화면 |
|---|---|---:|---|
| 0:00 | 입실 상태 유지 | 0.0030 A | 정상 |
| 0:05 | **스위치 누름** | 0.1535 A | — |
| 0:07 | 2회 연속 확인 | 0.1535 A | **설비 이상·과전류 critical → 차단** |
| 0:07 | LED 꺼짐 | 0.000 A | 차단 표시 |
| 0:10 | **스위치를 누른 채** 정지 3초 | 0.000 A | PRE-ALERT 배너 |
| 0:12 | 계속 정지 5초 | 0.000 A | **협착 critical** |
| 0:20 | 스위치 해제 | 0.000 A | 협착 유지 |

⚠ **스위치는 협착이 뜬 뒤에 놓는다.** 손을 떼는 동작이 `dop_std` 를 튀게 해
5초 카운트를 리셋할 수 있다(`STAT_RESET_DS = 0.38`, 3프레임 리셋).
시나리오상으로도 끼여 있으면 손을 못 뗀다.

**말할 것:** "작업 대상 설비 회로의 부하가 정상 3 mA 에서 151 mA 로 급증했습니다.
1초 간격 2회 연속 확인 후 해당 회로만 차단했습니다. 차단이 실제로 이루어진 것을
릴레이 readback 으로 확인한 뒤, 재실 상태에서 5초 연속 무동작이 관측되어
협착으로 확정했습니다."

→ 스위치 해제 확인 → `Event Resolved` → `CMD_RESTORE` 3중 확인 → LED 점등

### 시나리오 3 — 과전류 → 정상 복귀 (약 60초) · 오탐이 안 나는 것을 보여준다

| 시각 | 동작 | 화면 |
|---|---|---|
| 0:00 | 스위치 누름 | — |
| 0:02 | 차단 | 설비 이상·과전류 critical |
| 0:03 | **스위치 해제하고 ROI 안을 걸어다닌다 (10초)** | 협착 **안 뜸** |
| 0:15 | 퇴실 버튼 | 협착 게이트 닫힘 |

**말할 것:** "같은 차단 상태에서 작업자가 움직이면 협착으로 판정하지 않습니다.
협착 확정은 과전류 차단 성공 · 재실 · 5초 연속 무동작의 AND 조건입니다.


## 6. 예상 질문과 답변

**Q1. 낙상인데 왜 전원을 안 끊나?**
낙상은 신체 사고를 의미하지만 전기 설비가 원인이거나 구조자에게 활선 위험을
준다는 것을 증명하지 않습니다. 낙상 SOP 는 즉시 접근이고 전기 SOP 는 차단 확인
후 접근이라 조치가 다릅니다. 자동 차단은 전기·협착 확정 사건에만 적용합니다.

**Q2. 저항 하나 붙인 게 어떻게 협착인가?**
협착 시 구동부 부하가 급증하는 현상을 8V LED 회로로 모의한 것입니다. 협착 확정은
전류 하나가 아니라 차단 성공과 재실 무동작의 AND 조건입니다.

**Q3. 5초는 무슨 근거인가?**
안전 여유가 아니라 구분을 위한 최소값입니다. 차단은 이미 스위치 작동 2초 뒤에
끝났고, 5초는 그 뒤에 사고 유형을 라벨링하는 시점입니다. 에너지 격리는 이미
완료된 상태이므로 이 타이머가 인명 위험을 좌우하지 않습니다. 실측으로 조정할
예정입니다.

**Q4. 끼인 사람이 발버둥치면 무동작이 아니지 않나?**
그 경로는 별도로 있습니다. 과전류 차단이 확인된 상태에서 약 2초간 낮은 자세의 제한적
움직임이 지속되면 무동작을 기다리지 않고 협착으로 확정합니다. 다만 이 문턱은 이번
시연자의 동작을 기준으로 실측해 정한 것이고, 다른 두 명에서는 재현율이 4/10·1/10 이었습니다.
일반화된 협착 동작 인식이라고 주장하지 않으며, 일반 작업자에 대해서는 차단 후 5초 무동작
경로가 기본입니다.

**Q5. 오탐률은?**
낙상 판정 기준 난음성 5/86 = 5.81% 입니다. 이번 변경으로 줄지 않았습니다. 다만
차단 범위를 작업 대상 설비 회로 1개로 한정했기 때문에, 오탐이 나도 멈추는 것은

**Q6. 왜 레이더인가? 카메라가 낫지 않나?**
