# Radar-Guard UI/LLM 개편 계획 (2026-07-26)

멘토 지적: "그래프만 보여서 오실로스코프 같다. 전달하는 가치가 없다. LLM을 더 써라."
+ "3D 포인트 클라우드가 사람 형태로 안 보인다" → 노트북/젯슨 분리 제안.

이 문서는 **UI에서 LLM을 어떻게 쓸 것인가**를 중심으로 정리한다.

---

## 0. 먼저 정정하고 갈 것 — 포인트 클라우드는 freezing 문제가 아님

수집 데이터 실측 (프레임당 포인트 수):

| 파일 | 프레임 수 | 중앙값 | p90 | 최대 |
|---|---|---|---|---|
| events_bodytypes_final2.jsonl | 5,060 | 4 | 14 | 55 |
| events_final.jsonl | 13,500 | 8 | 31 | 97 |
| events_still.jsonl | 15,980 | 11 | 35 | 97 |

프레임당 점이 **4~11개**다. 프레임 드랍이 0이어도, 윈도우 노트북으로 옮겨도 점 8개는
사람 형태가 되지 않는다. mmWave + CFAR + 클러터 제거 후 남는 물리적 한계이지
연산 병목이 아니다.

멘토에게 "서버를 분리하면 사람 형태로 보일 것"이라고 답하면 다음 미팅에서 더 큰 타격이 된다.
프레이밍을 바꿔야 한다: **형태 복원은 이 센서로 불가능하므로, 원시 포인트를 보여주는 것을 그만둔다.**

다만 렌더 지연 자체는 실재한다. 원인은 젯슨보다 matplotlib 3D scatter 재그리기이며,
여기에 7/12에 확인된 Gemma 호출로 인한 렌더 루프 7초 스파이크가 겹쳤다.

### 3D 패널 대안 (원시 점 → 트랙 추상화)

1. **N프레임 누적** (5~10프레임): 점 40~80개로 밀도 확보. 오래된 프레임은 알파 감쇠.
2. **자세 프록시 오버레이**: 서있음 = 세로 캡슐 / 누움 = 가로 캡슐, 색 = 상태.
   반드시 "추정 형상(estimated posture)"으로 라벨링 — 실제 형상인 척하지 않는다.
3. **궤적 트레일 + 존 바닥 그리드**: 어디서 어디로 이동했는지가 점 개수보다 정보량이 크다.
4. 갱신 주기를 UI 렌더 주기와 분리 (3D는 5Hz로 충분, 텍스트 패널은 즉시).

## 1. 진단 — 지금 LLM이 가치 없어 보이는 3가지 구조적 원인

### (1) LLM 경로가 전부 꺼져 있다

`radar_live_full.py` 현재 상태:

```python
USE_LLM_SUMMARY    = False   # RAG 요약 LLM 비활성
DETAILED_SOP_POPUP = False   # [7/12] 젯슨 90s 타임아웃 + 렌더 7s 스파이크로 끔
```

즉 화면에 나오는 조치문은 전부 `INSTANT_ACTION_KO` 하드코딩 딕셔너리이고,
매뉴얼 패널은 pgvector 검색 원문을 그대로 붙인 것이다.
**현재 UI에서 LLM이 실제로 생성하는 문장은 하나도 없다.** 멘토 지적은 정확하다.

### (2) 켜도 템플릿과 구별되지 않는다

`_prewarm_gemma()`는 이벤트 유형 3종에 대해 다음과 같이 미리 생성해 캐시한다:

```python
txt = generate_detailed_sop(et, 'C', '')   # zone='C' 고정, manual_ctx='' 비움
```

즉 낙상이면 **언제·어디서·어떻게 넘어져도 항상 같은 문장**이 나온다.
입력이 상수면 출력도 상수다. 이건 LLM이 아니라 "느리게 만들어진 템플릿"이다.
심사위원이 두 번째 경보를 보는 순간 들통난다.

### (3) 시스템이 아는 것을 LLM에 알려주지 않는다

`classify()`는 판정 근거 수치를 이미 전부 계산한다:

| 변수 | 의미 | 실측 기준값 |
|---|---|---|
| `dopstd_max` | 도플러 격렬함 피크 | 낙상 임계 1.2 |
| `h_drop` | 창 내 높이 변화폭 | 낙상 최소 0.447 |
| `horiz_range` | 바닥평면 이동폭 | 낙상 0.75~1.26 / 빠른앉기 0.35~0.79 |
| `zacc_amp` | 수직 가속도 피크 | ⚠ `FALL_ZACC_MIN = 0` — 현재 게이트 무력화 상태 (아래 주석 참조) |
| `ds_broad` | dop_std≥0.8 프레임 수 | 낙상 2~5 / 노이즈 플래시 0~1 |
| `n_p75`, `conf` | 포인트 밀도, 신뢰도 | — |

> **부수 발견** — `zacc_amp` 관련 정리 필요:
> `FALL_ZACC_MIN = 0`(253행)이라 `_zacc` 조건이 항상 참이다. 즉 수직가속 게이트는
> 실질적으로 꺼져 있다. 또 572~580행 주석의 "보행 0.19 / 사건 0.67"은 642행의
> `zacc_amp >= 400`과 단위 스케일이 맞지 않아 옛 값으로 보인다.
> L2 근거 카드에 이 수치를 인용하려면 **먼저 실측 재확인**이 필요하다.
> (당장은 L2에서 `zacc_amp`를 빼고 `dopstd_max` / `h_drop` / `horiz_range` / `ds_broad` 4개만 쓴다.)

그런데 프롬프트에는 이것이 들어간다:

```python
f'방금 "{label}"이(가) Zone {zone}에서 감지됐다.'
```

**이벤트 이름과 존 이름뿐이다.** 그래프에는 데이터가 있고 LLM에는 데이터가 없다.
멘토가 "그래프만 보인다"고 한 것의 진짜 원인이 이것이다.

## 2. 설계 원칙 4가지

| # | 원칙 | 이유 |
|---|---|---|
| P1 | **관측값을 프롬프트에 주입한다** | 매 경보마다 다른 문장이 나와야 LLM의 값어치가 화면에 보인다 |
| P2 | **캐시는 골격까지만** | 유형별 매뉴얼 요약은 prewarm 가능. 실측 수치가 들어가는 브리핑·근거는 캐시 금지 |
| P3 | **모든 레이어에 폴백이 있다** | 3초 내 응답 없으면 규칙기반 문장(수치 포함) 표시 후 도착 시 교체. 폴백도 수치가 들어가 템플릿보다 낫다 |
| P4 | **UI 렌더를 절대 블로킹하지 않는다** | 7/12에 렌더 루프 7초 스파이크로 RESET 버튼이 먹통 됐던 원인 |

추가: **스트리밍 출력**(`"stream": true`)을 쓴다. 총 생성 시간이 8초여도 첫 토큰이
0.6초에 나와 글자가 흘러나오면 체감 지연은 사라진다. 심사에서 "AI가 지금 생각해서 쓰고 있다"는
인상 자체가 가치 전달의 절반이다.

## 3. LLM 레이어 4종

### L1 — 상황 브리핑 (Situation Brief)

경보 순간 화면 최상단에 뜨는 한국어 2~3문장. **UI의 새로운 주인공.**

- **트리거**: `_latch_event()` 직후
- **입력**: 이벤트 유형, 존, 시각, `h_drop`, `horiz_range`, 낙하 소요시간, 무동작 지속 s, `conf`, 직전 5분 상태 전이
- **지연 예산**: 첫 토큰 1초 / 완결 4초 (스트리밍)
- **캐시**: 없음 (수치가 매번 다름)
- **폴백**: 수치를 채운 규칙 문장

프롬프트 골자:

```
너는 안전 관제 요원이다. 아래 레이더 관측값을 관리자에게 보고하는 2~3문장을
한국어로 써라. 수치를 반드시 인용하고, 추측이나 미확인 사실을 덧붙이지 마라.

시각: 18:19:46 / 위치: C존
중심 높이: 1.68m → 0.31m (0.4초)
바닥평면 이동: 1.12m
이후 무동작: 12초 경과
분류: 낙상, 신뢰도 0.87
직전 5분: 보행 → 정지 3초 → 본 사건
```

출력 예:
> 18시 19분 46초, C존에서 사람의 중심 높이가 1.68m에서 0.31m로 0.4초 만에 떨어졌고
> 동시에 바닥면으로 1.12m 이동했습니다. 쓰러진 뒤 12초째 움직임이 없습니다.
> 낙상으로 판단되며 신뢰도는 87%입니다. 즉시 확인이 필요합니다.

### L2 — 판단 근거 (XAI) ★ 그래프를 대체하는 핵심

"왜 이렇게 판단했는가"를 문장으로 설명하는 카드. **z 그래프와 dop_std 그래프가 하던 말을 여기서 한다.**

- **트리거**: L1 완료 직후 (또는 사용자가 "근거" 버튼 클릭)
- **입력**: `classify()`의 피처 값 + 임계치 + RF veto 결과 + 기각된 후보 클래스
- **지연 예산**: 5초 (덜 급함)
- **폴백**: 규칙 기반 근거 생성기 (임계 비교문 자동 조립)

출력 형태 — **근거 3줄 + 반례 1줄**:

> **근거**
> · 도플러 격렬함 1.87 (낙상 임계 1.2 초과), 0.8 이상 프레임 4개로 순간 노이즈 아님
> · 높이 변화폭 1.37m (낙상 최소 기준 0.447m)
> · 바닥평면 이동 1.12m — 제자리 빠른앉기 범위(0.35~0.79m)를 벗어남
>
> **기각한 후보**
> · 진동/기계 오탐 아님: 도플러 주기성 없음, RF veto 통과
> · 빠른앉기 아님: 수평 이동이 앉기 범위 초과

이 카드가 들어가면 그래프는 "보조 근거"로 강등되어 하단에 작게 두어도 된다.
심사위원이 "이 시스템은 왜 그렇게 판단했는지 설명한다"고 인식하는 지점이 여기다.

### L3 — 매뉴얼 근거 조치 (RAG SOP)

이미 구현된 pgvector 검색을 살리되, 세 가지를 고친다.

1. `_prewarm_gemma()`의 `zone='C'`, `manual_ctx=''` 고정을 제거. prewarm은 "유형별 매뉴얼
   요약"까지만 만들고, 존·시각·수치는 표시 시점에 주입한다.
2. **출처 표기 필수**: `d.metadata['source_file']`을 각 조치 옆에 표기. 환각 방어이자
   "매뉴얼에 근거한 조치"라는 주장의 증거다.
3. 검색 실패 시 `INSTANT_ACTION_KO`로 강등 (현행 유지).

- **지연 예산**: 8초 (L1/L2가 먼저 화면을 채우므로 여유 있음)
- **캐시**: 유형별 골격 캐시 O, 최종 문장 캐시 X

### L4 — 자연어 질의 (Ask) ★ "에이전트"의 근거

관제자가 시스템에 직접 묻는 입력창. 과제명이 **안전관리에이전트**인 만큼 이게 있어야
"에이전트"라는 이름이 성립한다.

- **입력**: 사용자 질문 + `state['incidents']` + `state['logs']` + (선택) 매뉴얼 RAG
- **질의 예시**:
  - "밤사이 특이사항 있었어?"
  - "오늘 C존에서 몇 번 경보 났어?"
  - "아까 그 낙상, 오탐 아니야?"
  - "보호자한테 보낼 문자 써줘" → 통보 문안 자동 생성
- **지연 예산**: 10초 (사용자가 기다리는 맥락)
- **폴백**: 필터/집계 결과를 표로만 표시

여기에 **통보 문안 자동 생성**을 포함시키면 "그래서 뭐가 좋아지는가"에 대한
즉답이 화면 안에 존재하게 된다.

## 4. 이게 왜 그래프를 대체하는가 (멘토 설득용 대응표)

| 현재 패널 | 전달하던 것 | 대체 |
|---|---|---|
| Centroid Height 그래프 | 높이 곡선을 보고 사람이 해석 | L2가 "1.68m→0.31m, 0.4초" 로 진술 |
| dop_std + 임계선 | 선을 넘었는지 사람이 판독 | L2가 "1.87 vs 임계 1.2" 로 진술 |
| 3D 포인트 클라우드 | 점 8개 | 누적 + 자세 프록시 + L1 문장 |
| Incident History | 시각 로그 나열 | 유지 (+ L4로 질의 가능) |
| Action Guide | 하드코딩 SOP | L3 (매뉴얼 출처 표기) |

**그래프를 없애지는 않는다.** 하단 접이식으로 내리고, L2 근거 카드에서 특정 수치를
클릭하면 해당 그래프 구간이 강조되도록 연결하면 "숫자 → 근거 → 원신호"의 계층이 생긴다.

## 5. 노트북 ↔ 젯슨 분리 토폴로지

멘토 제안 방향은 타당하나, 역할을 뒤집는 편이 낫다. 젯슨이 UI까지 그리면
matplotlib 3D 렌더가 젯슨 CPU를 그대로 먹어 지연이 남는다.

```
[윈도우 노트북]                          [Jetson Orin Nano — headless]
 레이더 UART 수신                          ollama serve (gemma2:2b, keep_alive 30m)
 → 클러터 제거 / extract_features          pgvector (safety_manual)
 → classify()                             REST: /brief /explain /sop /ask
 → UI 렌더 (3D·그래프·텍스트)      ──────▶  이벤트 JSON 수신
 → LLM 결과 스트리밍 수신          ◀──────  토큰 스트림 반환
```

- **통신**: 이벤트 JSON over HTTP(스트리밍) 또는 WebSocket. 같은 공유기 유선 권장.
- **폴백**: 젯슨 무응답 3초 → 규칙 기반 문장으로 자동 강등, 로그에 `LLM degraded` 표기.
  도착하면 교체. **데모가 젯슨 상태에 인질로 잡히지 않게 한다.**
- **심사 방어논리**: "센서 엣지 / AI 추론 엣지 2단 분산. 영상·원본 데이터를 외부로
  전송하지 않는 온디바이스 추론 구조." → 젯슨을 쓰는 이유가 오히려 더 명확해진다.
- **모델**: gemma2:2b 유지 (7/4 팀 결정 근거 유효 — Q4 1.6GB, OOM 여유, TPS 우위).

1초 만에 보여주는 배치다.

## 7. 작업 순서

| 단계 | 내용 | 선행조건 | 검증 기준 |
|---|---|---|---|
| S1 | 이벤트 JSON 스키마 확정 (classify 피처 전부 포함) | — | 실제 경보 1건의 JSON에 표의 6개 수치가 다 있음 |
| S2 | 젯슨 headless LLM 서버 (`/brief` 스트리밍) | S1 | 노트북에서 curl로 첫 토큰 1초 내 수신 |
| S3 | L1 + 폴백 + UI 스트리밍 표시 | S2 | 젯슨 끄고도 UI가 수치 문장 표시 |
| S4 | L2 근거 카드 + 규칙 기반 폴백 생성기 | S1 | 같은 이벤트 3회에 서로 다른 수치 문장 |
| S5 | L3 prewarm 수정 + 출처 표기 | S2 | 매뉴얼 출처 파일명이 화면에 표시됨 |
| S6 | 3D 누적 + 자세 프록시 | — | 표시 포인트 40개 이상, 렌더 5Hz 유지 |
| S7 | L4 질의창 | S2, S3 | 3가지 질문에 사실 오류 없는 답변 |
| S8 | 그래프 접이식 하단 이동 | S3, S4 | 렌더 루프 스파이크 1초 미만 |

S1~S4까지만 끝나도 멘토 지적의 본질은 해소된다. S6~S8은 그 다음이다.

## 8. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| 젯슨 생성 지연 (7/12에 90s 타임아웃 실측) | 데모 중 빈 화면 | 스트리밍 + 3초 폴백. 폴백에도 수치가 들어감 |
