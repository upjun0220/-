## 1. 무엇이 문제였고 왜 동결하는가

**문제.** 8/19 시연에서 낙상 3회가 하나도 잡히지 않았다. 원인은 판정식이 아니라
프레임 처리율이었고(9.96fps → 1.55fps, 백로그 42.3초), 그 뒤 3주 동안 판정 주변
코드가 반복해서 수정됐다. 8/20 배타 latch 도입, 8/21 8V 임계 교체와 배타 latch
제거, 8/22 협착 5초 전환, 8/24 협착 Shadow 추가다. 그때마다 "낙상은 안 건드렸다"는
확인이 필요했고 매번 diff 를 사람이 다시 읽어야 했다.

**8/24 시점의 상태.** 낙상·과전류·협착·감전 모의 경로가 실물에서 전부 정상 동작하는
것을 확인했다. 즉 지금이 **처음으로 검증된 기준선**이다.

**결정.** 이 상태를 고정한다. 판정에 관여하는 코드는 UI 작업을 포함한 어떤 작업에서도
수정하지 않는다. 수정이 필요하면 작업 전에 홍유빈의 허락을 받는다.

동결의 직접적인 계기는 오늘 저녁 예정된 UI 작업이다. `console_ui.py` 와
`radar_core.py` 는 `radar_common.py` 를 공유하고, `radar_common.py` 에는 표시용
문구와 판정용 임계가 같은 파일에 섞여 있다. 표시 문구를 고치다 `EVENT_SEV` 나
`CURR_LIMIT` 을 건드리면 화면이 아니라 차단 동작이 바뀐다. 그 사고를 막는 것이
이 문서의 목적이다.

### 2-2. `radar_common.py` 안의 판정 항목

젯슨과 노트북이 공유하는 파일이라 통째로 동결할 수 없다. 항목 단위로 나눈다.

| 기하 | `CEILING_H` `FRAME_INNER_HALF` `ENTRY_BAND` `OCCUPANCY_CORE_HALF` `HISTORY_LEN` |
| 상태기계 | `PH_*` `PHASE_ORDER` |
| 구역 | `RADAR_ZONE` `ZONE_IDS` `ZONE_EQUIPPED` `ZONE_DEVICE` `EVENT_ZONE` |
| 등급·차단 | `SEV_RANK` **`EVENT_SEV`** **`AUTO_TRIP_EVENTS`** |
| 전기 임계 | **`CURR_LIMIT`** **`VOLT_MIN`** `POWER_CONFIRM` `LEAK_LIMIT` `LEAK_CONFIRM` `VIB_DS_THRESH` |
| 공통 | 모든 딕셔너리의 **키**(이벤트 타입 문자열) |

기준값:

```

LEAK_LIMIT = 0.008       LEAK_CONFIRM = 2       VIB_DS_THRESH = 0.20
CEILING_H = 2.30         FRAME_INNER_HALF = 0.72    ENTRY_BAND = 0.18
```

`AUTO_TRIP_EVENTS` 에 `fall_detected` 가 없는 것은 실수가 아니라 8/24 결정이다.
낙상은 경보만 내고 자동 차단하지 않는다. 근거는 `REVIEW.md` RV-012 계열 논의다.

## 3. 수정해도 되는 것 — UI 작업 범위

- `01_현행코드/console_ui.py` — 표시 전용. 자유롭게 수정한다.
- `01_현행코드/radar_core.py` — 표시 전용. 자유롭게 수정한다.
  단 **판정을 UI 에서 다시 계산해서 그리지 않는다.** 젯슨이 보낸 결과만 그린다
  (`AGENTS.md` §0-2 원칙과 동일).
- `radar_common.py` 의 표시 항목 — **값만** 바꾼다. **키는 못 바꾼다.**
  `PHASE_KO` `PHASE_ACTION` `EVENT_KO` `ZONE_KO` `SEV_KO` `GATE_META` `REJECT_KO`
  `EVIDENCE_KO` `BREAKER_SCOPE` · 팔레트 전체(`BG` ~ `FS_*`, `SEV_COLOR`, `SEV_BG`)

`EVENT_LABELS` 는 젯슨 콘솔 로그용 영문 문자열이다. 값은 바꿔도 되지만 젯슨 로그
포맷이 바뀌므로 사후 분석 스크립트와 어긋날 수 있다. 건드리지 않는 편이 낫다.

## 4. 작업 후 검증 절차

```bash
git --no-optional-locks diff --stat 01_현행코드/
sha256sum 01_현행코드/jetson_sender.py 01_현행코드/verify_jetson_safe.py
grep -nE "^(CURR_LIMIT|VOLT_MIN|POWER_CONFIRM|LEAK_LIMIT|LEAK_CONFIRM|VIB_DS_THRESH) *=" 01_현행코드/radar_common.py
grep -n "AUTO_TRIP_EVENTS" -A4 01_현행코드/radar_common.py
python 01_현행코드/verify_jetson_safe.py
```

합격 기준

| 검사 | 기대 |
|---|---|
| `jetson_sender.py` diff | 0줄 |
| SHA-256 3개 | 2-1 표와 일치 |
| 전기 임계 6개 | 2-2 기준값과 일치 |
| `AUTO_TRIP_EVENTS` | 원소 6개, `fall_detected` 없음 |
| `verify_jetson_safe.py` | 종료코드 0 |

하나라도 어긋나면 커밋하지 않고 되돌린다.

⚠ `jetson_sender.py` 는 현재 CRLF 와 LF 가 섞여 있어 `git diff` 가 실제 변경보다
훨씬 크게 나온다(8/21 기준 실변경 205줄이 5,022줄로 표시). 판단은
`--ignore-all-space` 를 붙인 diff 와 SHA-256 으로 한다. 줄바꿈 정규화는 별도 항목이다.

## 5. 함께 동결되는 결정 — 협착 PINCH 판정은 '시연 전용'으로 채택됐다

⚠ 이 절의 초판(8/24 오전)에는 "협착 동작 판정 미채택"이라고 적혀 있었다. **오기다.**
그 판단은 **구 shadow 규칙**(`dop_mean >= 0.38` · `height_mean <= 1.00` · `n_mean <= 18.0`,
30프레임)에 대한 것이었고, 8/24 오후에 채택된 규칙은 다른 규칙이다.

### 5-1. 채택된 규칙 (동결 대상)

`jetson_sender.py` 는 파일 전체가 동결이지만, 가장 최근에 정해진 판정값이므로 명시한다.

```
PINCH_SHADOW_WIN      = 20      # 20프레임(약 2초) 롤링 창
PINCH_SHADOW_SEC      = 2.0
PINCH_DS_MEAN_MIN     = 0.33
PINCH_DS_MAX_MAX      = 0.59
PINCH_HEIGHT_MEAN_MAX = 0.83
```

게이트: `LIVE + 입실 + 차단 readback 성공(reason=overcurrent)` 에서만 버퍼를 채운다.
통과하면 기존 `설비 이상·과전류 Critical` 을 종료하지 않고 같은 사건에 `협착 Critical`
을 병렬 추가한다(`control_trip=False` — 추가 차단 없음).

### 5-2. 한정 조건 — 일반화된 협착 판정이 아니다

| 근거 | 수치 |
|---|---|
| 시연자 A PINCH 재현율 | 8/10 (Codex 보고) · 7/10 (Cowork 재현, 창 열거 차이) |
| 시연자 A 정상 30건 오탐 | 0건 (walk·crouch·still 전부) |
| 사람 B / C PINCH 재현율 | 4/10 / 1/10 — **일반화 안 됨** |

**이것은 A 의 고정 연기를 인식하는 영상 시연 전용 규칙이다.** 발표·문서에서
"협착 동작을 인식한다"고 일반화해서 말하지 않는다. `README.md` 8/24 A절과 같은 선을 지킨다.

### 5-3. Cowork 독립 검증에서 추가로 확인된 것 (README 미기재)

보유 데이터 135건(8/21 105건 + 8/24 pinch 30건)에 규칙을 그대로 적용했다.

**(a) `ds_mean > 0.33` 조건은 사실상 아무것도 거르지 않는다.**

| 라벨 | `ds_mean` 중앙 | 범위 | 0.33 초과 |
|---|---:|---|---:|
| pinch | 0.409 | 0.353~0.460 | 100% |
| walk | 0.387 | 0.360~0.466 | 100% |
| crouch | 0.393 | 0.361~0.421 | 100% |
| still | 0.352 | 0.340~0.370 | 100% |

빈 방 `dop_std` 실측이 0.319~0.327 이고 `still` 최솟값이 0.340 이다. 문턱 0.33 은 그
아래에 있다. 실제로 거르는 것은 `ds_max <= 0.59`(**큰 움직임 배제** — walk 가 전 인원
0/10 인 이유)와 `height_mean <= 0.83`(낮은 자세)이다.
즉 규칙의 실체는 "낮은 자세로 있으면서 크게는 움직이지 않음" 이다. 동작 인식이 아니다.

**(b) 사람 B·C 는 정지 상태에서도 통과한다.**

| 라벨 | A | B | C |
|---|---|---|---|
| PINCH (8/24) | 7/10 | 5/10 | 1/10 |
| walk | 0/10 | 0/10 | 0/10 |
| crouch | 0/5 | 2/5 | 1/5 |
| **still** | **0/10** | **6/10** | **9/10** |

`still` 의 `height_mean` 중앙값이 A 0.982 / C 0.752 로 갈린다. C 는 서 있어도 0.83 아래다.

운영상 위험은 없다 — 게이트가 과전류 차단 후이고, 그 상태의 무동작은 어차피 5초 경로로
`pinching` 이 뜬다. 2초에 먼저 뜰 뿐 사건 종류가 같다.
**시연상 위험은 있다.** 시연자가 A 가 아니면 PINCH 는 거의 안 뜨고 정지는 자주 뜬다.

→ **시연자를 A 로 고정한다.** `04_문서/진행보고/시연_런북_0824.md` 사전점검 항목이다.

### 5-4. 남는 한계

- 규칙이 낮은 자세에 의존하므로, **서서 팔만 끼인 협착**은 잡히지 않는다.
- 일반 작업자에 대한 협착 동작 판정은 여전히 미해결이다. 추가 수집을 한다면 사람 수보다
  **세션 반복**(같은 사람, 다른 날·옷·위치)이 먼저다. 구 규칙이 무너진 축이 사람이 아니라 세션이었다.

## 6. 해제 조건

동결은 아래 중 하나가 충족되고 홍유빈이 명시적으로 해제할 때만 풀린다.

1. 시연·발표 일정이 끝났다.
2. 판정 변경이 불가피한 결함이 발견됐고, 변경 전후를 같은 데이터로 비교할 준비가 됐다.
3. 새 임계를 정할 실측 데이터가 확보됐다(현재 미확정 항목은 7절).

## 7. 동결된 상태로 남아 있는 미확정 항목

동결은 "이 값들이 옳다"는 뜻이 아니라 "지금 바꾸지 않는다"는 뜻이다.

| 항목 | 상태 |
|---|---|
| `STAT_CRIT_SEC = 5.0` | 실측 근거 없는 판단값 |
| `STAT_RESET_DS = 0.38` | 빈 방 `dop_std` 0.319~0.327 대비 여유 0.05. 정지한 사람 실측 없음 |
| `VOLT_MIN = 7.50` | 3초 표본 2회. 작동 중 최저 7.73V 대비 여유 0.23V |
| `LEAK_LIMIT = 0.008` | 정상 최대 5.0mA 와 1kΩ 분기 최소 11.5mA 사이. 표본 적음 |
| 낙상 오탐률 | 난음성 5/86 = 5.81%. 이번 변경으로 줄지 않았다 |
| ROI 내 이동 추적 | `walk` 라벨 30건의 3초 무게중심 직선거리 중앙값 0.15 m. 걷기를 추적하지 못하거나 피험자가 제자리걸음만 했다 — 데이터로 구분 불가 |
