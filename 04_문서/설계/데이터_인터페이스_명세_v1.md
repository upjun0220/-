## 0. 이 문서가 존재하는 이유

`classify()`는 판정 근거 수치를 **전부 계산한 뒤 return에서 버린다.**

```python
# radar_live_full.py 641행 (현재)
return {'event_type': 'fall_detected', 'severity': 'critical', 'confidence': 0.87}
```

`dopstd_max` · `h_drop` · `horiz_range` · `ds_broad` · `zacc_amp` · `h_desc`가 지역변수로 살다 사라진다. **이것이 "그래프에는 데이터가 있고 LLM에는 데이터가 없다"(README 7/27 A절)의 실체다.** L2 판단 근거 카드는 이 수치들로 만들어지므로, 스키마가 이 값들을 실어 나르지 못하면 노트북은 또 그래프밖에 못 그린다.

### 설계 원칙

| # | 원칙 | 귀결 |
|---|---|---|
| 1 | **원본 포인트클라우드는 판정 결과와 함께만 나간다** | 보안 서사가 구조로 증명됨. 표시용 상한 64점 |
| 2 | **`event`는 유실되면 안 되고 `frame_status`는 유실돼도 된다** | 소켓 2개로 분리, HWM·CONFLATE 정책 다르게 |
| 3 | **누적·형상추정·렌더는 전부 노트북이 한다** | 젯슨은 프레임 원본만 송신. 시각화 개선이 판정에 영향 0 |
| 4 | **fail-safe** | 이 통로는 "보여주기용". 끊겨도 젯슨은 판정·차단 독립 수행 |
| 5 | **모든 수치는 단위·출처 라인을 명시** | L2 카드에 인용될 값이므로 추적 가능해야 함 |

## 1. 전송 방식

**ZeroMQ PUB/SUB**, 페이로드는 순수 JSON(UTF-8). 향후 WebSocket 전환 시 페이로드 재사용 가능.

| 소켓 | 포트 | 토픽 | 빈도 | 유실 정책 |
|---|---|---|---|---|
| `frame_status` | tcp://*:5556 | `status` | 10 Hz | **CONFLATE=1** — 최신 1건만 유지. 늦은 구독자는 과거 프레임을 못 봐도 무방 |
| `event` | tcp://*:5557 | `event` | 사건 시 | **HWM=1000**, `seq` 단조증가. 노트북이 `seq` 건너뜀을 감지해 화면에 "유실 N건" 표시 |
| `query` (L4, 노트북→젯슨) | tcp://*:5558 | REQ/REP | 사용자 입력 시 | 타임아웃 5s → 폴백 |
| `command` (제어, 노트북→젯슨) | tcp://*:5559 | REQ/REP | 조작 시 | 타임아웃 3s. **실패해도 젯슨 로컬 제어는 유효** |

> ⚠ ZMQ PUB은 HWM 초과 시 **조용히 버린다.** `frame_status`는 그것이 올바른 동작(최신만 필요)이지만, `event`에는 `seq`를 넣어 유실을 **감지 가능하게** 만든다. 유실 자체가 안전 문제는 아니다 — 젯슨이 이미 차단을 수행했고 서버는 안전 조치의 필수 경로가 아니기 때문(fail-safe). 다만 화면이 조용히 거짓말하는 것은 막아야 한다.

```json
{
  "schema_version": 1,
  "type": "frame_status",
  "seq": 184213,
  "ts": 1785000000.123,
  "step": "LIVE",

  "centroid": {"cx": 0.12, "cy": 1.23, "cz": -0.34},
  "height": 1.07,
  "n_pts": 8,
  "dop_std": 0.34,
  "int_mean": 142.5,
  "z_vel": -0.21,
  "z_accel": 38.4,

  "zone_state": {"A": "NORMAL", "B": "NORMAL", "C": "PRE_ALERT"},
  "zone_timer": {"C": 3.2},

  "ae_score": 0.0182,
  "ae_thr": 0.0250,

  "points": [[0.10, 1.20, -0.30], [0.14, 1.26, -0.38]],
  "points_truncated": false,

  "health": {
    "fps": 9.8,
    "cpu_pct": 41.2,
    "ram_mb": 4380,
    "llm": "remote_ok",
    "raw_egress_count": 0
  }
}
```

### 필드 사전

| 필드 | 단위/범위 | 출처 (`radar_live_full.py`) | 소비처 |
|---|---|---|---|
| `seq` | 단조증가 int | 신규 | 유실 감지 |
| `ts` | unix epoch float(초) | 신규 | 반사실 타이머 |
| `step` | `BASELINE`/`TRAIN`/`LIVE` | 기존 상태변수 | 상태 스트립 |
| `centroid.cx/cy/cz` | m. **cy = 센서로부터의 range(수직축)**, (cx,cz) = 바닥평면 | feat[0],[1],[2] | 3D 정합 기준점 |
| `height` | m. `CEILING_H(2.30) - cy` | 215행 | L1 문장 |
| `n_pts` | 개. 실측 중앙값 4~11 | feat[6] | 3D, 신뢰도 |
| `dop_std` | m/s | feat[4] | L2, 그래프 |
| `z_vel` / `z_accel` | m/s, m/s² | feat[7],[8] | 보조 |
| `zone_state` | `NORMAL`/`PRE_ALERT`/`ALERT` | `DANGER_ZONES` 113행 | 존 표시 |
| `zone_timer` | 초. 정지 지속시간 / `STAT_HOLD_SEC` | 게이트 로직 | PRE-ALERT 진행바 |
| `ae_score`/`ae_thr` | LSTM-AE 재구성오차 / 임계 | `score`,`thr` | L2 "정상범위 대비 N배" |
| `points` | `[[x,y,z],…]` m, **상한 64** | 프레임 원본 | 3D 누적 |
| `points_truncated` | 상한에 걸려 잘렸는지 | 신규 | 정직성 표시 |
| `health.raw_egress_count` | 항상 0이어야 함 | 신규 | **보안 주장의 화면상 증거** |

> ⚠ **`points` 상한 64는 사실상 발동하지 않는다.** 각 분해능 약 28°로 인해 원본이 프레임당 4~11개다(README 7/27 참조). 상한은 이상 상황 방어용이며, 이 값을 올려도 포인트는 늘지 않는다.

## 3. `event` — 사건 발생 시

**`evidence` 블록이 이 스키마의 존재 이유다.** L2 판단 근거 카드가 전적으로 여기서 만들어진다.

```json
    "ae_thr":      0.0250
  },

  "gates": {
    "impulse":  {"value": 8.90, "thr": 2.2,  "unit": "비율", "pass": true},
    "h_drop":   {"value": 1.37, "thr": 0.43, "unit": "m",    "pass": true},

  "breaker": {"action": "trip", "target": "PANEL_C", "result": "ok", "latency_ms": 120},
  "window": {"frames": 15, "t_start": 1785000000.0, "t_end": 1785000001.5}

```

### `evidence` 필드 출처 (전부 `classify()` 내 기존 지역변수)

| 필드 | 계산 라인 | 의미 | 실측 기준값 |
|---|---|---|---|
| `dopstd_max` | 560 | 창 내 dop_std 피크 | 낙상 ≥1.2, 타 동작 ≤1.16 |
| `dopstd_mean` | 561 | 지속 움직임 세기 | — |
| `ds_first`/`ds_last` | 565/566 | 창 전·후반부 평균 | 낙상 후 가라앉음 (`ds_last` ≤1.0) |
| `ds_broad` | 593 | `dop_std ≥ 0.8` 프레임 수 | 낙상 2~5, 플래시 0~1 |
| `impulse_ratio` | 633 | `dopstd_max / max(0.15, ds_first)` | 낙상 2.3~7.9 |
| `h_drop` | 568 | 창 내 높이 변화폭 | 낙상 최소 0.447, 팔휘두름 0.424 |
| `h_desc` | 591 | 피크 **이전** 평균높이 − **이후** 평균높이 | 낙상 +0.20~+0.70, 그 외 ≤0 |
| `horiz_range` | 576 | 바닥평면 이동폭 `hypot(Δcx, Δcz)` | 낙상 0.75~1.26, 빠른앉기 0.35~0.79 |
| `zacc_amp` | 580 | 수직가속 피크 | ⚠ 아래 경고 참조 |
| `n_mean`/`n_p75` | 562/563 | 포인트 수 평균/75분위 | 보행 `n_p75` ≥15 |

> ⚠ **`zacc_amp`는 전송하되 L2 카드에 인용 금지 (현 시점).**
> `FALL_ZACC_MIN = 0`(253행)이라 `_zacc` 게이트가 항상 참으로 무력화 상태이고, 572~580행 주석의 "보행 0.19 / 사건 0.67"이 642행 `zacc_amp >= 400`과 **스케일이 맞지 않는다**(옛 값으로 추정). 실측 재확인 후 `gates`에 승격할 것. 그때까지 L2는 `impulse`/`h_drop`/`horiz`/`ds_last`/`ds_broad` 5개만 사용.

### `gates` / `rejected` 를 젯슨이 만드는 이유

L2 카드("왜 낙상인가 + 왜 다른 게 아닌가")를 **LLM이 지어내지 않게** 하기 위해서다. 통과한 게이트와 기각된 후보를 젯슨이 사실로 확정해 보내면, 노트북 LLM은 그것을 **한국어 문장으로 바꾸기만** 한다. LLM이 죽어도 `gates`를 그대로 표에 뿌리는 규칙 기반 폴백이 성립한다(README S5 완료 기준).

## 3-B. `command` — 제어 (노트북 → 젯슨, REQ/REP)

> **⚠ 설계 원칙: 제어는 젯슨 로컬에 반드시 남는다. 노트북 채널은 편의 기능이지 유일 경로가 아니다.**
> baseline/training/RESET을 노트북에만 두면 **노트북이 죽었을 때 젯슨을 초기화조차 못 한다** — fail-safe 위반이다. 따라서 아래 명령은 전부 젯슨 로컬(기존 GUI 버튼 또는 headless CLI 인자)에 **동일하게 존재해야 하며**, 노트북은 같은 함수를 원격 호출할 뿐이다.

```json
// 요청
{"schema_version": 1, "cmd": "start_baseline", "args": {}, "req_id": "a3f1"}
// 응답
{"schema_version": 1, "req_id": "a3f1", "ok": true, "step": "BASELINE", "msg": "빈방 스캔 12s 시작"}
```

| `cmd` | 인자 | 대응 로컬 조작 | 비고 |
|---|---|---|---|
| `start_baseline` | — | `[START Baseline]` 버튼 | 빈방 12s 스캔 |
| `start_training` | — | `[Start Training]` 버튼 | 정지 15s → LIVE 진입 시 baseline 자동 저장 |
| `reset` | — | `[RESET]` 버튼 | 상태·타이머 초기화 |
| `resolve_event` | `event_seq` | 수동 이벤트 해제 | README 4순위 UX |
| `get_state` | — | — | 노트북 재접속 시 현재 상태 동기화 |

### v2 이후로 미루는 것

**차단기 원격 수동 트립(`breaker_trip`)은 v1에서 제외한다.** 현장 액추에이터를 네트워크 너머에서 조작 가능하게 만들면, "차단은 네트워크가 끊겨도 독립 동작한다"는 fail-safe 서사와 정면으로 충돌한다. 관제실 수동 차단은 실무에서 정상 기능이지만 별도 안전 설계(인터록·권한·감사로그)가 필요하므로 MVP 범위 밖이다.

### RF 재수집은 이 채널을 기다리지 않는다

`radar_collect.py`는 **젯슨 터미널 단독 도구**이고 런북이 이미 존재한다(README 「오늘 할 일 — 라벨 데이터 수집 Runbook」). AE baseline/training도 젯슨 기존 matplotlib GUI 버튼으로 지금 가능하다. → **노트북 UI 완성을 기다리지 말고 즉시 수집을 시작할 것.** 이것이 젯슨 matplotlib UI를 당장 삭제하면 안 되는 실질적 이유다.

## 4. 노트북 소비 매핑

| 화면 요소 | 사용 필드 |
|---|---|
| **L1 상황 브리핑** | `event_type`, `zone`, `height_start→height_end`, `ts`, `confidence` |
| **L2 근거 카드** | `gates` 전체 + `rejected` + `ae_score`/`ae_thr` |
| **L3 SOP(RAG)** | `event_type` → pgvector 검색 (bge-m3) + 출처 파일명 |
| **L4 질의** | `event` 이력 버퍼 + `frame_status` 최근 N |
| **3D 트랙 뷰** | `points`(누적), `centroid`(정합 기준), `height`(자세) |
| **존 패널** | `zone_state`, `zone_timer` |
| **젯슨 상태 스트립** | `health.*` |
| **반사실 타이머** | `event.ts` − 낙상 추정시각, `breaker.latency_ms` |

## 5. 젯슨측 최소 변경

> **⚠ `radar_live_full.py`(122KB)를 리팩터링하지 말 것.** 7/10~7/12 라이브 디버깅으로 확정한 상수가 전부 이 파일에 있다. 구조를 건드리면 그 튜닝이 조용히 깨진다. **추가만 한다.**

### 변경 1 — `classify()` return에 evidence 부착

모든 피처가 계산된 직후(약 600행, `conf` 산출 뒤)에 dict 하나를 만들고, 이후 **모든 return에 `'evidence': _ev, 'gates': _gates`를 덧붙인다.** 판정 로직은 한 줄도 건드리지 않는다.

```python
# [신규] 피처 계산 완료 지점에 삽입 — 판정 로직 무변경
_ev = {
    'dopstd_max': round(dopstd_max, 3), 'dopstd_mean': round(dopstd_mean, 3),
    'ds_first': round(ds_first, 3), 'ds_last': round(ds_last, 3),
    'ds_broad': int(ds_broad),
    'impulse_ratio': round(dopstd_max / max(0.15, ds_first), 2),
    'h_drop': round(h_drop, 3),
    'h_desc': (round(h_desc, 3) if h_desc is not None else None),
    'horiz_range': round(horiz_range, 3), 'zacc_amp': round(zacc_amp, 1),
    'n_mean': round(n_mean, 1), 'n_p75': round(n_p75, 1),
    'height_start': round(CEILING_H - cy_vals[0], 2),
    'height_end':   round(CEILING_H - cy_vals[-1], 2),
    'ae_score': round(float(score), 4), 'ae_thr': round(float(thr), 4),
}
```

`_zacc`는 `FALL_ZACC_MIN = 0`이라 항상 참이므로 `gates`에서 제외한다(위 경고).

### 변경 2 — PUB 송신부 (신규 파일 `radar_pub.py`)

`radar_live_full.py`에 소켓 코드를 섞지 않는다. 별도 모듈로 두고 import 한 줄 + 호출 두 줄만 추가한다. **송신 실패는 절대 판정 루프를 막지 않는다** — `try/except` + `NOBLOCK`.

```python
# radar_pub.py — 젯슨. 실패해도 판정에 영향 없어야 함
import zmq, json, time, os
_ctx = zmq.Context.instance()
_st = _ctx.socket(zmq.PUB); _st.setsockopt(zmq.CONFLATE, 1)
_st.bind(os.environ.get('PUB_STATUS', 'tcp://*:5556'))
_evs = _ctx.socket(zmq.PUB); _evs.setsockopt(zmq.SNDHWM, 1000)
_evs.bind(os.environ.get('PUB_EVENT', 'tcp://*:5557'))
_seq = {'status': 0, 'event': 0}

def _send(sock, topic, payload):
    try:
        _seq[topic] += 1
        payload.update(schema_version=1, seq=_seq[topic], ts=time.time())
        sock.send_multipart([topic.encode(),
                             json.dumps(payload, ensure_ascii=False).encode()],
                            zmq.NOBLOCK)
    except Exception:
        pass          # 관제 전송 실패는 판정·차단에 영향 없음 (fail-safe)

def publish_status(d): _send(_st,  'status', d)
def publish_event(d):  _send(_evs, 'event',  d)
```

### 변경 3 — `--headless` 유지, matplotlib UI 삭제 금지

노트북 UI가 검증될 때까지 젯슨 GUI가 **유일한 대조 수단**이다. 44행 `--headless` 플래그로 켜고 끄며 병행 운용하다가, 노트북 화면이 동등함을 확인한 뒤 끈다.

## 6. 3D 시각화 — 노트북 전용 파이프라인

**센서는 사람 모양을 못 준다.** 각 분해능 약 28°, 센서 2.3m에서 가로 1.2m가 한 덩어리로 뭉개진다(어깨너비 0.45m). **단일 프레임에서 실루엣은 물리적으로 불가능하며, 이는 연산 위치와 무관하다.** 따라서 시각화는 시간축 누적으로 만든다. **전 과정이 노트북에서만 일어나므로 판정 영향은 0이다.**

| 단계 | 처리 | 효과 |
|---|---|---|
| ① 버퍼 | 최근 10프레임(=1초 @10Hz) 링버퍼 | 8점 → 약 **80점** |
| ② 정합 | 각 프레임 점을 그 프레임 `centroid` 기준 상대좌표로 변환 → 최신 `centroid`에 재배치 | 이동 중에도 형태 유지 (미정합 시 궤적으로 뭉개짐) |
| ③ 형상추정 | 누적 점군에 PCA. 제1주축이 **수직**이면 서있음(세로 캡슐) / **수평**이면 누움(가로 캡슐). 고유값으로 길이·폭 | "사람 같은" 형상 |
| ④ 렌더 | 반투명 캡슐 + **원본 점 동시 표시**(작게) + 궤적 트레일 + 존 바닥 그리드. 5Hz | 3D 뷰 완성 |

**라벨 필수**: `추정 형상 (최근 1초 / 10프레임 누적, 원시 8점)`

**심사 방어 논리** — 원본 점을 숨기지 않고 캡슐과 **함께** 표시하고 "추정"을 명시하므로 과장이 아니다. 판정은 원본 점으로만 수행하고 캡슐은 표시 전용이다. 시간축 누적은 SLAM·의료영상에서 표준 기법이다.

**한계 (정직하게 보고할 것)** — 2인 이상이 같은 존에 있으면 누적이 섞인다. 단 `classify()` 주석에 명시된 **"원칙은 Zone당 1명 스코프"**와 일관되므로 새로운 제약이 아니다.
