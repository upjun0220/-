처음 보고 시점에는 `jetson_sender.py` 가 **문법 검증만** 통과한 상태였습니다(py_compile).
문법 통과 ≠ 실행이라, 실제로 돌려보니 **버그 3개**가 나왔습니다. 전부 고쳤습니다.

### 새로 생긴 실행 방법

```powershell
# [창 1] 레이더·젯슨·torch 없이 진짜 jetson_sender.py 를 구동
python jetson_sender.py --simulate --fast
# [창 2]
python console_ui.py --live 127.0.0.1
```

`--simulate` 는 `radar_parser.py` 를 대신해 **같은 JSONL 포맷**으로 합성 프레임을 흘려 넣습니다.
그래서 파일 tail 읽기 → 파싱 → 피처추출 → classify(RF 검증 포함) → 차단기 → 패킷조립까지
**실제 코드 경로가 전부 돕니다.** `sim_jetson.py`(병렬 구현)와 달리 프로덕션 코드를 검증합니다.
`--fast` 는 스캔 3s·웜업 30프레임으로 줄여 한 사이클 24초 — UI 반복 작업용입니다.

### 잡은 버그 3개

**① 학습 실패 시 영구 정지** ⚠ 가장 심각
`_train_worker` 에 try/except 가 없어서 `train_on_real_data` 가 예외를 던지면
`_done` 이 영원히 set 되지 않고 `while not _done.wait(...)` 가 무한 대기했습니다.
**TRAINING 화면에서 조용히 멈추고 아무 메시지도 안 나옵니다.** `pipeline_loop_safe` 도
못 잡습니다(메인 스레드에 예외가 없으므로). torch 문제·OOM·데이터 부족 어느 것으로든 재현됩니다.
→ 예외 포착 + 180초 타임아웃 + 실패 시 **규칙 전용 LIVE 로 강등**. 정지보다 강등이 안전합니다.

**② 규칙 전용 강등이 오히려 탐지를 죽이는 문제**
①을 고치면서 `thr = 1e9` 로 뒀는데, AE 는 점수가 아니라 **classify 앞의 게이트**였습니다
(`is_anomaly = score > thr` → `anom_streak` → `classify`). thr 을 크게 잡으면
**classify 가 아예 호출되지 않아 낙상을 하나도 못 잡습니다.** → `thr = -1.0` 으로 게이트를 개방.
추가로 `ae_disabled` 플래그가 없으면 웜업 블록으로 무한 재진입해 phase 가 LIVE→WAIT_TRAIN 으로
되돌아갔습니다(실측 재현: 웜업 카운트 155→183 무한 증가).

**③ 웜업 중 차단기가 내려감**
`classify_equipment(curr, volt, dop_std)` 에 사람의 `dop_std` 를 먹이고 있었습니다.
`VIB_DS_THRESH=0.20` 은 '정지된 장면 속 기계 진동' 기준인데 **걷는 사람의 dop_std 가 0.2~0.5**
라서 사람이 걸을 때마다 차단됐습니다. 게다가 웜업·학습 중에도 판정했습니다.
→ LIVE 에서만 판정하고, 진동은 `classify()` 의 `vibration_anomaly`(지속성 게이트 있음)에 맡기고,
per-frame 에서는 전기 이상(과전류·전압강하)만 봅니다.

### 3번 — console_ui UDP 전환 + 시스템 준비 팝업 ✅
- ZMQ(5556/5557) 폐기 → 승원이의 UDP(5005/5006) + HELLO 자동 발견 채택
- 수신을 **QThread + pyqtSignal** 로 분리 → 도착 즉시 렌더. QTimer 100ms + 레이더 100ms 앨리어싱 소멸

  젯슨은 RTC 배터리가 없어 부팅마다 시계가 틀어지고, 그러면 배너에 "-3600초 경과"가 떴을 겁니다
- **'시스템 준비' 팝업 신설**: READY/WARMUP/WAIT_TRAIN/TRAINING/LIVE 5단계 진행바 + 기준 수집 시작/학습 시작/기준 초기화.

- **경보 상태기계 완성** (어제 지적한 "돌아오는 길이 없다"):
  ```
  NORMAL ─경보→ UNACK(점멸+비프) ─확인함→ ACK(정지, 경보는 유지) ─상황 종료→ NORMAL
  ```

- `PoseEstimator.label` 노출 — "추정 형상 · 최근 10프레임 누적" 이 화면에 뜹니다
- 3D에 1m·2m 높이 눈금 링, 시점 초기화 버튼
- 평상시 화면에 **무경보 연속 시간** · 가동시간 · 패킷 유실 수

```
상황종료      NORMAL   True   False  TRIPPED    1    1     ← LOTO 유지 ✓
전력복구      NORMAL   True   False       ON    1    1
```

### 패킷 크기 — 단편화 해소
매 패킷에 히스토리(cz/ds/sc 각 120개 + logs + incidents)를 싣던 것을 **1초에 한 번**으로 분리했습니다.
```
       개선 전                개선 후
평시    3,964 B (3조각)   →   736 B 중앙 / 최대 1,085 B  ✓ 단일 이더넷 프레임
히스토리       —          →   2,863 B (1Hz, 3조각) — 유실돼도 1초 뒤 복구
대역폭                        11.1 KB/s  (100Mbps의 0.09%)
```
WiFi에서 조각 하나 잃으면 패킷 전체가 사라지는 위험을 90% 구간에서 제거했습니다.
그래도 **데모는 유선 직결 + 고정 IP를 권합니다.**
